# 7주차 3일차 공부일지 — JavaScript 객체 배열, DOM 연결, Event Loop

## 오늘의 핵심 3줄
1. 객체 배열은 `배열 → 객체 하나 → property` 순서로 접근한다.
2. 계산 함수는 값을 `return`하고, DOM 변경은 다른 함수가 맡는다.
3. event listener는 등록만 되고, Call Stack이 비었을 때 실행된다.

## 오늘 한 일

### JavaScript 객체와 객체 배열
- JavaScript 객체(Object)와 property를 학습하고, 객체 여러 개를 배열에 넣어 다루는 방법을 배웠다.
- `products`는 배열 전체, `products[i]`는 객체 하나, `products[i].price`는 그 객체의 property 값이라는 구조를 반복해서 확인했다.
- 객체 배열을 반복문과 연결해 조건을 검사하고 개수를 세는 연습을 했다.

### DOM과 event
- 객체 배열과 `querySelectorAll()`로 가져온 NodeList를 같은 index로 연결해 여러 DOM 요소의 `textContent`를 변경했다.
- 버튼에는 `addEventListener("click", 함수)` 형태로 함수 자체를 등록했고, click event가 발생한 뒤 객체 배열의 데이터를 화면에 표시했다.

### CS
- Call Stack, Web APIs, Task Queue, Event Loop의 기본 흐름을 학습했다.
- event가 발생해도 현재 실행 중인 함수가 있으면 listener 함수가 바로 실행되지 않고, Call Stack이 비었을 때 실행된다는 흐름을 확인했다.

## 막힌 부분과 시도한 것

### 1. 변수 선언 누락
- **막힌 부분**: 독립 재현에서 `30000`원 이상 상품 개수를 세는 새 변수를 만들면서 `let` 선언을 빠뜨렸다.
- **시도한 것**: 계산 함수 안에서 `let count30000 = 0`으로 변수를 선언하고 다시 실행했다.

### 2. 함수 역할이 분리되지 않음
- **막힌 부분**: 계산 함수가 결과를 `return`해야 했는데, 처음에는 계산 함수 안에서 DOM까지 직접 변경했다.
- **시도한 것**: 계산 함수는 결과를 `return`하도록 고치고, 별도의 함수가 그 반환값을 받아 DOM의 `textContent`를 변경하도록 나눴다. 버튼에는 함수 자체를 event listener로 등록했다.

### 3. 변수명과 property명 혼동
- **막힌 부분**: `title`을 `name`으로 쓰거나 `productPrice` 대신 `productName`을 쓰는 등, 실제 선언된 이름과 다르게 쓰는 실수가 있었다.
- **시도한 것**: 객체 배열을 다룰 때 `배열 → 객체 하나 → property 값` 순서로 지금 다루는 값이 무엇인지 추적했다.

## 배운 점
- 객체 배열에서는 배열에서 객체 하나를 먼저 선택한 뒤 필요한 property에 접근해야 한다.
- 함수 parameter에 무엇이 들어가는지는 함수 이름이나 parameter 이름이 아니라, 호출할 때 전달한 argument가 결정한다.
- 계산 함수는 값을 계산해 `return`하고, DOM 변경 함수가 그 값을 받아 화면을 수정하도록 역할을 나눌 수 있다.
- 새 변수를 만들 때는 선언 여부를 먼저 확인해야 하고, 이후 재할당이 없다면 `let`보다 `const`가 더 적절하다.
- event listener는 등록해 두는 것이고, 실행 시점은 Call Stack이 비었을 때다.

## 아직 부족한 부분
- 새 변수를 만들 때 `let`이나 `const` 선언을 빠뜨리는 실수가 반복되고 있다.
- 객체 구조는 이해하고 있지만, 코드를 쓰는 중에 실제 변수명과 property명을 확인하지 않고 쓰는 경우가 있다.
- 계산과 DOM 변경을 어떤 함수가 담당할지 스스로 나누는 판단이 아직 안정적이지 않다.
