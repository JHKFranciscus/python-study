# 8주차 6일차 공부일지

**키워드**: Flask, jQuery Ajax, JSON, DOM 렌더링, append(), data-*, this, .data(), 동적 route, type="button"

**한 줄 요약**
Flask가 JSON으로 돌려준 데이터를 JavaScript가 직접 반복해서 HTML로 만들고 화면에 붙이는 흐름을 처음 배웠고, 그 흐름으로 메모 등록·조회와 할 일 done 상태 변경까지 연결했다.

---

## 오늘 한 일

- Flask와 jQuery Ajax를 이용해 메모를 등록하고 조회한 뒤, 서버에서 받은 데이터를 현재 페이지의 DOM에 다시 표시하는 전체 흐름을 구현했다.
- POST /memo에서는 request.form으로 title, content를 받아 Python 리스트에 저장했고, GET /memo에서는 전체 메모를 JSON으로 반환했다.
- JavaScript에서는 Ajax로 받은 배열을 반복하면서 각 메모의 값을 HTML 문자열로 만들고 append()로 화면에 표시했다.
- 등록 버튼도 Ajax POST 방식으로 연결해 페이지 이동 없이 메모를 저장하고, 저장 성공 후 다시 전체 목록을 조회해 화면을 갱신했다.
- 요구사항 기반 재구성과, 구조가 다른 독립재현을 진행했다.
- 마지막에는 data-*, this, .data(), 동적 route를 연결해 특정 할 일의 done 상태만 변경하고, 변경 후 전체 목록을 다시 받아 화면에 반영했다.

---

## 막힌 점

**1. Ajax로 받은 여러 객체를 화면에 표시하는 방법**
가장 크게 막힌 부분이다. 지금까지는 Flask가 데이터를 넘기고 Jinja의 {% for %}가 HTML을 반복 생성하는 방식만 썼다. JavaScript가 배열을 직접 반복하면서 HTML 문자열을 만들고 DOM에 추가하는 방식은 처음부터 작성하지 못했다. 확인해 보니 이전에 배우지 않은 연결 방식이었고, 설명을 받은 뒤에 구현했다.

**2. 등록 버튼에서 Ajax 요청과 form submit이 같이 나가는 문제**
type="submit" 버튼에 Ajax click handler까지 연결하면서 Ajax 요청과 form submit이 동시에 발생했다.

**3. 구조가 다른 독립재현에서의 연결 오류**
동적으로 만들어진 상태 변경 버튼에 event를 연결하는 부분에서 막혔다. 그 외에 route 문자열 불일치, response["i"]와 response[i] 혼동, DOM 대상 누락, 동적으로 만든 버튼의 attribute 오류가 있었다. 최종적으로는 버튼 생성 시 onclick="changeStatus(this)"를 함께 넣는 방식으로 정리했다

## 시도한 것

**1. Jinja 방식으로 처리해 보다가 실행 시점의 차이를 확인**
처음에는 Ajax로 받은 데이터도 기존 Jinja 방식과 비슷하게 처리하려 했다. 그러다 Jinja는 서버가 HTML을 만들 때 실행되고, Ajax response는 페이지가 이미 만들어진 뒤에 JavaScript가 받는 값이라는 차이를 확인했다.

**2. 서버 로그에 요청이 두 건 찍힌 것을 확인**
서버 로그를 확인해 보니 요청이 두 건 찍혀 있었고, 여기서 Ajax 요청과 form submit이 둘 다 나가고 있다는 것을 확인했다. 버튼을 type="button"으로 바꿔 Ajax 요청만 실행되도록 수정했다.

**3. 구조를 먼저 직접 작성한 뒤 오류를 하나씩 수정**
독립재현에서는 전체 조회와 상태 변경 구조를 먼저 직접 작성했고, 실제 실행 과정에서 발생한 오류를 하나씩 수정해 최종 동작을 확인했다.

## 배운 점

**1. Ajax로 받은 데이터를 화면에 표시하는 흐름**

```
JSON 배열
→ 배열에서 객체 하나씩 꺼냄
→ 객체의 값 추출
→ HTML 문자열 생성
→ DOM에 추가
```

**2. submit과 Ajax는 요청을 보내는 주체가 다르다**
submit은 form 자체의 기본 동작이고, Ajax는 JavaScript가 별도의 HTTP 요청을 보내는 방식이다. 그래서 한 버튼에 둘 다 걸려 있으면 요청이 두 번 나간다.

**3. Flask가 반환하는 구조가 JavaScript의 response 구조를 그대로 결정한다**

- `jsonify(memos)` → response 자체가 배열이다.
- `jsonify({"result": "success", "memos": memos})` → `response["memos"]`로 접근해야 한다.

## 추가로 정리한 개념

HTTP 요청을 다음 기준으로 구분했다.

- URL: 대상
- method: 수행하려는 작업
- query string: 조회 조건
- request body: 서버에 전달할 실제 데이터
- response: 서버 처리 결과

## 아직 부족한 부분

- JavaScript에서 배열을 반복해 HTML을 만들고 DOM에 추가하는 방식은 오늘 처음 배웠기 때문에, 아직 독립적으로 자연스럽게 작성할 수준은 아니다.
- 요구사항 기반 재구성과 구조가 다른 독립재현에서는 전체 구조의 상당 부분을 직접 만들었지만, 여러 연결 오류를 안내받아 수정했으므로 독립 성공으로 평가하지 않는다.
- 특히 다음 연결을 더 안정적으로 재현해야 한다.
  1. Flask 반환 구조 → JavaScript response 구조
  2. 여러 객체 → 객체 하나 → 객체 내부 값
  3. data-* → 클릭한 요소 → this → .data() → Ajax → 동적 route → 특정 서버 데이터 → DOM 갱신
