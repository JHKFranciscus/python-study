# 2026-09-08 공부일지

## 한 줄 요약
optional 조건(날짜, 과목)을 조합해 MongoDB를 조회하는 GET API 하나를 만들고,
JavaScript에서 filter 값을 읽어 query string으로 넘기는 흐름까지 연결했다.

---

## 오늘 한 일
- Flask GET API에서 optional query parameter를 받아 MongoDB query dictionary를 동적으로 구성했다. 날짜만 / 과목만 / 날짜+과목 / 조건 없음, 네 경우를 API 하나로 처리했다.
- JavaScript에서 filter의 `.value`를 읽어 `URLSearchParams`로 query string을 만들고, 완성된 request URL을 `fetch()`에 전달했다.
- `<input>`과 `<select>`의 `change` event에 자동 재조회를 연결하고, 초기화는 `.value`를 `""`로 바꿔 전체 조회로 되돌렸다.
- 허용되지 않은 query parameter value는 Flask에서 validation해 `400`을 반환하도록 했다.
- 같은 기능을 도서 대여 기록으로 독립 재현했다. (날짜별 / category별 / 동시 조회 / 조건 변경 시 재조회 / 초기화 / 잘못된 category의 400 / 결과 DOM 표시)
- SSAFY 개인 문제집은 다른 일정 때문에 오늘은 하지 않았다.

## 막힌 부분
- URL query string(`date=2026-09-08&subject=Python`)과 Python dictionary(`{"date": "2026-09-08", "subject": "Python"}`)의 표기를 혼동했다.
- DOM element인 `recordList`와 `recordList.innerHTML`을 혼동해 `recordList = ""`라고 썼다.
- `response.status`와 `response.ok`를 한 번 혼동했다.
- `books`(collection)와 `book`(element 하나)의 역할을 잘못 판단했다.
- 독립 재현 중 resource 경로, DOM id와 parameter 철자, `response.json()`의 `return` 위치, 빈 `<option>`, Python 자료구조 문법, 400 response 작성에서 오류가 났고 Claude의 교정과 디버깅을 받아 해결했다.

## 시도한 것
- 변수 이름만 보지 않고, 그 변수에 지금 실제로 무엇이 들어 있는지를 따라갔다.
  - server: `request.args → query dictionary → find() → Cursor → list → jsonify()`
  - client: `DOM element → .value → URLSearchParams → query string → request URL → fetch()`
- filter 값을 function 밖에서 한 번만 저장하지 않고, 조회 function이 실행될 때마다 다시 읽게 했다.
- 조회할 때 기존 DOM 내용을 먼저 비운 뒤 새 결과를 표시했다.
- 독립 재현은 완성 코드를 보고 따라 쓰지 않고, 요구사항만 보고 Flask / HTML / JavaScript의 큰 구조를 직접 잡았다.
- 오류를 고친 뒤 브라우저에서 실제로 동작하는지 다시 확인했다.

## 알게 된 것 (면접용)
- **query와 결과는 다르다.** query는 DB에서 무엇을 찾을지 정하는 조건이고, 결과는 그 조건으로 조회된 document들이다.
- **조건이 몇 개든 API는 하나면 된다.** 빈 dictionary에 들어온 조건만 추가하면 여러 조회 조합을 GET API 하나로 처리할 수 있다. 한 dictionary 안의 여러 field 조건은 기본적으로 AND로 적용된다.
- `find()`의 결과는 Cursor이고, `list()`를 거쳐야 document를 담은 Python list가 된다.
- `URLSearchParams` / query string / 완성된 request URL은 서로 다른 값이다. DOM element / `.value` / `innerHTML`도 서로 다른 대상이다.
- `addEventListener()`에는 나중에 실행할 function 자체를 전달하고, callback 안에서 즉시 실행할 때는 function을 직접 호출한다.
- `response.status`는 구체적인 HTTP status code, `response.ok`는 성공 여부를 나타내는 boolean이다. 400을 받아도 `fetch()`의 다음 `.then()`이 자동으로 멈추지는 않는다.
- **조회 결과 0개와 잘못된 request는 다른 상황이다.** application 고유의 허용값은 HTTP가 검사해주지 않으므로 server 코드에서 직접 validation해야 한다.

## 아직 모르는 것
- `response.ok === false`일 때 Promise chain을 error 처리 흐름으로 분리하는 방법은 아직 배우지 않았다.
- 긴 Flask + JavaScript 코드를 처음부터 쓸 때 변수명, DOM id, query parameter 이름, `return` 위치, collection과 element를 끝까지 정확하게 유지하는 것이 부족하다.
- 독립 재현에서 전체 구조는 직접 구성했지만, 세부 구현 정확도는 아직 독립 완성 수준이 아니다.

## 내일 할 것
- 오늘 독립 재현이 안 됐다는 이유로 보충일로 바꾸지 않고, 4단계의 다음 본 진도를 진행한다.
- 진도 중에도 `현재 변수의 value/type → 필요한 역할 → 다음 parameter로 전달되는 값`을 계속 추적한다.
