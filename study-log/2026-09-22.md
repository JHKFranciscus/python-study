# 공부일지 · 2026-09-22

**한 줄 요약** — 6단계 첫 모의시험에서 Flask + MongoDB + JavaScript CRUD는 직접 구현했지만, validation 일부를 놓쳐 피드백 후 직접 보완했다.

**키워드** — `CRUD 구현 ≠ 명세 구현` · `400 / 404 구분` · `response.ok → throw`

---

## 1. 오늘 한 일
- 5단계 AWS 배포를 마치고 6단계 첫 웹 모의시험을 시작했다.
- 시설 장애 신고 관리 서비스를 요구사항만 보고 직접 구현했다.
  - 신고 등록
  - 조회: 전체 / 조건(category · priority · status filter) / 날짜 범위 / latest · oldest 정렬
  - status 수정(PATCH), 삭제(DELETE)
  - 수정·삭제 후 현재 filter를 유지한 채 재조회

## 2. 독립적으로 한 것
CRUD 전체 골격과 아래 흐름을 직접 구성했다.

```
JavaScript → Flask → MongoDB → Flask → JavaScript → DB 기준 화면 재조회
```

특히 POST / GET / PATCH / DELETE에서 path, query, body를 구분해 연결하는 부분은 독립적으로 구현했다.

## 3. 피드백으로 보완한 것
완전 독립 성공은 아니다. 최초 구현에서 아래 validation을 놓쳤고, 피드백으로 누락 지점을 확인한 뒤 직접 수정했다.
- `required field` POST 필수 field key 누락 검사
- `allowed value` GET category / priority / status / sort 허용값 검사
- `allowed value` PATCH update_status 허용값 검사

## 4. CS 확인 (오늘 구현한 API 기준)
- method / path / query / body 구분: GET은 query parameter, PATCH는 path parameter + body
- `fetch()`는 400 / 404 응답만으로는 reject되지 않는다. → `response.ok` 확인 후 `throw`해서 `.catch()`로 넘겼다.
- ObjectId 형식이 틀리면 `400`, 형식은 맞는데 document가 없으면 `404`로 구분했다.
- `matched_count == 1`, `modified_count == 0`도 가능하다. (찾긴 했지만 실제로 바뀐 값은 없는 경우)

## 5. 오늘의 결론
```
CRUD를 구현할 수 있다 ≠ 명세를 빠짐없이 구현했다
```
전체 application 구조와 CRUD 연결은 독립적으로 할 수 있었다.
부족했던 건 CRUD가 아니라 명세 확인이었다. 다음 모의시험에서는 구현 전에 validation과 HTTP 응답 조건을 먼저 분리해 확인해야 한다.

## 6. 다음 모의시험 — 구현 전에 명세에서 먼저 분리할 것
```
required field
allowed value
400 조건
404 조건
성공 status code
```

## 7. SSAFY
개인 사정으로 오늘만 생략했다. 실패·미완료·다음 날 이월로 처리하지 않는다.

**30초 스크립트**
> 첫 웹 모의시험에서 요구사항만 보고 Flask, MongoDB, JavaScript로 CRUD 서비스를 구현했습니다. 전체 CRUD와 path, query, body 연결은 직접 구성했지만 validation 일부를 놓쳐 피드백 후 수정했습니다. 이 경험으로 기능 구현과 명세 충족은 다르다는 걸 확인했고, 이후에는 구현 전에 필수값, 허용값, 400·404 조건을 먼저 분리해 확인하려고 합니다.


**예상 꼬리질문**
- 400과 404는 어떻게 나눴나요? → ObjectId 형식이 틀리면 400, 형식은 맞는데 document가 없으면 404.
- fetch 오류 처리는 어떻게 했나요? → 400 / 404만으로는 reject되지 않아서 `response.ok` 확인 후 `throw`해 `.catch()`로 넘겼다.
- validation은 왜 놓쳤나요? → 명세 조건을 처음부터 전부 체크하지 못했다고 그대로 인정하고, 다음부터 구현 전에 5가지 조건을 먼저 분리하겠다고 답한다.
