# 2026-07-30 공부일지

## 한 줄 요약

- 객체를 JSON 파일로 저장하고 다시 객체로 복원하는 전체 흐름을 직접 구현하고 확인했다.

## 오늘 한 일

- 클래스 객체를 JSON 파일에 저장하기 위해 `to_dict()`로 객체를 딕셔너리로 변환했다.
- JSON의 `type` 값을 확인해 `Product`와 `DownloadProduct` 객체를 다시 만드는 복원 함수를 작성했다.
- 상품 전체 조회, 검색, 가격 변경, 삭제, 저장, 불러오기 기능을 구현했다.
- 숫자로 된 문자열은 `int`로 변환하고, 숫자가 아닌 값과 음수 가격은 거부하도록 처리했다.
- 파일이 없거나 JSON 형식이 잘못된 경우 빈 목록을 반환하도록 예외 처리를 작성했다.
- 도서 관리 프로그램을 보지 않고 JSON 기반 상품 관리 프로그램을 처음부터 다시 구현했다.
- CS에서 직렬화·역직렬화와 메모리 객체·파일 데이터의 차이를 정리했다.

## 막힌 부분

- 테스트를 초기 상태로 되돌리려고 넣은 파일 삭제 코드와, 실제 프로그램에서 데이터를 유지해야 하는 구조를 구분하지 못했다.
- 파일 삭제 코드를 제거한 뒤 기존 데이터를 불러오면서 초기 상품도 다시 등록하면 중복이 생긴다는 점을 놓쳤다.
- `json.load()`가 JSON을 `list`와 `dict`로 바꾸는 단계와, 복원 함수가 새 인스턴스를 만드는 단계를 구분하지 못했다.
- 메모리의 객체 값만 바꾸면 JSON 파일도 같이 바뀌는지 설명하지 못했다.

## 시도한 것

- 실행할 때마다 JSON 파일을 삭제하던 코드를 제거했다.
- 불러온 상품 목록이 비어 있을 때만 초기 상품을 등록하도록 조건을 추가했다.
- 알 수 없는 `type`이라 복원 함수가 `None`을 반환하면 상품 목록에 추가하지 않도록 처리했다.
- 가격 변환 과정에서 `ValueError`와 `TypeError`를 모두 처리했다.
- 가격 변경 후 값과 자료형을 출력해 문자열이 아닌 `int`로 저장됐는지 확인했다.
- 저장한 뒤 새 `ProductManager`를 만들어 클래스 종류와 가격이 그대로 복원되는지 확인했다.
- CS 답안에 처음 쓴 답을 남기고 `[수정]`을 덧붙여 이전 판단과 교정 내용을 비교했다.

## 배운 것

- 직렬화는 메모리의 데이터를 저장하거나 전송할 수 있는 형식으로 바꾸는 과정이다.
- 역직렬화는 JSON 데이터를 Python의 `list`, `dict`, `str`, `int` 같은 자료형으로 바꾸는 과정이다.
- `json.load()`는 사용자 정의 클래스의 인스턴스까지 자동으로 복원하지 않는다.
- `create_product_from_dict()`는 딕셔너리의 값을 이용해 새 `Product` 또는 `DownloadProduct` 인스턴스를 만든다.
- 메모리의 객체와 디스크의 JSON 파일은 별개의 데이터라서, 객체를 바꿔도 파일은 자동으로 바뀌지 않는다.
- 프로그램을 종료한 뒤에도 바뀐 값을 유지하려면 객체를 딕셔너리로 바꿔 JSON 파일에 다시 써야 한다.
- 파일을 유지하는 프로그램에서는 데이터가 없을 때만 기본 데이터를 등록해야 중복을 막을 수 있다.

- JSON 파일의 일부만 수정하는 방식과 전체를 다시 저장하는 방식의 차이를 정확히 모른다.
- 데이터를 자주 검색하고 수정할 때 JSON 대신 데이터베이스를 쓰는 이유를 아직 구체적으로 설명하지 못한다.
