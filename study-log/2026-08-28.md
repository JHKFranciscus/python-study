## 오늘 한 일

**1. GET / POST Ajax 흐름**
- GET Ajax 요청으로 서버 데이터를 조회하고, `jsonify()`로 받은 JSON response를 JavaScript에서 사용했다.
- POST Ajax 요청에서는 값을 request body에 담아 보내고, Flask의 `request.form`에서 받아 실제 서버 데이터를 수정한 뒤 변경 결과를 다시 JSON으로 반환했다.

**2. 클릭된 버튼 특정하기**
- HTML의 `data-*` attribute와 jQuery의 `.data()`를 새로 배웠다.
- 여러 버튼 중 실제로 클릭된 버튼을 `this`로 특정하고, 여기서 얻은 식별값을 Ajax request와 DOM 변경에 연결했다.

**3. `redirect()`와 Ajax 비교**
- 처리 후 다른 페이지를 새로 요청해야 하는지, 아니면 현재 페이지를 유지하면서 일부만 변경해야 하는지를 기준으로 response 방식을 판단했다. (→ 부록 비교표)

**4. 즐겨찾기 토글 기능 구현**
- `list 안의 dictionary` 구조에서 책을 id로 찾아 `favorite` 값을 반전시키고, 변경된 book을 JSON으로 반환해 해당 책의 상태만 화면에서 변경했다.

**5. 실제 연결해서 실행**
- `templates`와 `static` 폴더를 구성하고 `render_template()`과 `url_for("static", filename=...)`을 이용해 HTML, JavaScript, Flask를 실제로 연결해서 실행했다.

## 배운 점

**1. Ajax에서는 서버 데이터가 바뀌어도 화면이 자동으로 바뀌지 않는다.**
Flask가 response를 보내고, 그 response를 받은 JavaScript가 **직접 DOM을 변경해야** 화면이 바뀐다.

**2. 하나의 식별값이 기능 전체를 연결한다.**

```
HTML의 data-* attribute
→ JavaScript
→ URL 또는 request body
→ Flask
→ 서버 데이터 식별
→ JSON response
→ JavaScript
→ DOM 요소 식별
```

**3. request에 필요한 정보가 전부 body에 들어가는 건 아니다.**
식별값이나 동작의 의미는 URL에 둘 수도 있고, 변경할 값은 body에 둘 수도 있다. 요구사항과 API 설계를 보고 각각의 위치를 판단해야 한다.

## 아직 부족한 부분

- 요구사항을 보고 필요한 데이터가 **동적 route / query string / request body** 중 어디에 있어야 하는지 즉시 판단하는 능력
- Flask가 반환한 데이터 구조를 보고 JavaScript의 `response` 구조를 바로 예상하는 것 (설명을 듣고 이해는 했지만, 먼저 예상하는 건 아직)
- `data-*` → `this` → Ajax → Flask → DOM으로 식별값이 이동하는 흐름 (오늘 처음 배웠고 설명 듣고 이해한 단계라 반복 필요)


## B. `redirect()` vs Ajax 비교표

| 항목 | `redirect()` | Ajax |
| --- | --- | --- |
| 페이지 이동 | 다른 페이지를 새로 요청 | 현재 페이지를 유지 |
| response | 새 페이지 요청으로 이어짐 | JSON |
| 화면을 바꾸는 주체 | 브라우저가 새 페이지를 그림 | JavaScript가 DOM을 직접 변경 |
| 선택 기준 | 처리 후 다른 페이지로 넘어가야 할 때 | 현재 페이지에서 일부만 바꿔야 할 때 |

## C. 예상 꼬리질문 & 정직한 답변 방향

**Q1. `redirect()`랑 Ajax는 어떤 기준으로 나눠 쓰나요?**
→ 처리 후 다른 페이지를 새로 요청해야 하면 `redirect()`, 현재 페이지를 유지하면서 일부만 바꿔야 하면 Ajax를 씁니다.

**Q2. 여러 버튼 중에서 클릭한 버튼을 어떻게 특정했나요?**
→ HTML의 `data-*` attribute에 식별값을 넣고, 클릭 시 `this`로 클릭된 버튼을 특정한 뒤 jQuery의 `.data()`로 값을 꺼냈습니다. 처음 배우는 내용이라 흐름이 바로 연결되지 않아서 ChatGPT 설명을 듣고 이해했고, 이해한 뒤에 Ajax request와 DOM 변경까지 연결했습니다. 다만 안 보고 바로 쓰는 건 아직 반복 연습이 필요합니다.

**Q3. response 구조를 잘못 접근한 적이 있나요?**
→ Flask가 `tasks[task_id]` 하나만 반환했는데 JavaScript에서 다시 `response[task_id]`로 접근한 적이 있습니다. 이건 제가 디버깅으로 찾은 게 아니라 ChatGPT 설명을 듣고 이해한 부분입니다. 서버가 무엇을 반환하는지 먼저 확인해야 한다는 걸 배웠고, 반환 구조를 바로 예상하는 건 아직 연습 중입니다.

**Q4. 화면이 안 바뀌었을 때 어떻게 접근했나요?**
→ 서버 문제인지 JavaScript 문제인지부터 분리했습니다. Console에 response를 출력해 서버에서 값이 정상적으로 반전되는 걸 확인한 뒤, 남은 범위인 DOM 선택 쪽에서 class selector의 `.` 누락을 찾았습니다.

**Q5. 그 기능은 혼자 만든 건가요?**
→ 그날은 독립재현 블록이 세 개(필수 6·7·8) 있었고, 그중 필수 8은 구조를 다르게 해서 재현하는 블록이었습니다. 필수 8은 전체 구조의 상당 부분을 직접 만들었지만 여러 오류를 안내받아 수정했기 때문에, 처음부터 끝까지 독립적으로 성공한 것은 아닙니다. 수정 후 실제 실행까지 정상 동작하는 것은 확인했습니다.

**Q6. 식별값이 URL에 들어갈지 body에 들어갈지는 어떻게 정하나요?**
→ 요구사항과 API 설계를 보고 판단해야 한다는 건 알지만, 동적 route / query string / request body 중 어디인지 즉시 판단하는 건 아직 부족합니다. 그래서 코드부터 쓰지 않고 설계 순서를 먼저 밟는 연습을 하고 있습니다.
