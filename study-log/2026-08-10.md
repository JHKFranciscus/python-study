# 6주차 1일차 공부일지

**주제: Python — 함수 객체와 decorator**

---

## 한 줄 요약

함수 객체의 전달과 인수 있는 decorator의 연결 구조를 이해했지만, 요구사항만 보고 독립적으로 설계하는 데는 실패했다.

---

## 오늘 한 일

- collection 전체와 요소 하나를 구분하고, 변수의 현재 값을 추적했다.
- 함수 호출부에서 실제 인수가 매개변수에 어떻게 들어가는지 역추적했다.
- `func`와 `func()`를 구분하고, 함수 객체를 인수와 반환값으로 쓰는 흐름을 연습했다.
- 인수를 받는 decorator의 연결을 다시 확인하고, 마지막에 통합 문제를 혼자 재현해봤다.

---

## 배운 점 (면접에서 말할 핵심)

**1. `func`는 함수 자체, `func()`는 실행 결과다.**
지금 필요한 것이 함수인지 실행 결과인지를 기준으로 판단한다.

**2. 매개변수에 들어온 값은 함수 정의가 아니라 호출부에서 역추적한다.**
변수 이름으로 값을 추측하지 않는다.

**3. collection인지 요소인지는 데이터가 어디서 꺼내졌는지를 보고 판단한다.**

**4. 인수 있는 decorator는 값이 단계별로 나뉘어 전달된다.**
`@repeat(3)`은 `repeat(3)(원래 함수)` 형태로 풀린다.
decorator 인수, 원래 함수, 실제 호출 인수가 서로 다른 단계에서 전달된다.

**5. decorator가 원래 함수의 결과를 가공하려면, 원래 함수의 반환값을 받아서 다시 반환해야 한다.**

---

## 막힌 점

- `@decorator(인자)`의 인자 자리에 함수 자체도 들어갈 수 있다는 것을 바로 연결하지 못했다.
- decorator 인수 → 원래 함수 → wrapper의 실제 호출 인수를 각각 어느 함수가 받아야 하는지 독립적으로 구성하지 못했다.
- 최종 통합 문제에서 여러 함수의 역할과 데이터 흐름을 처음부터 설계하지 못했다.

---

## 시도한 것

- 변수의 값을 이름으로 추측하지 않고, 대입문과 호출부를 따라가며 확인했다.
- `func`/`func()`는 지금 필요한 것이 함수 자체인지 실행 결과인지를 기준으로 판단했다.
- decorator는 `@repeat(3)`을 `repeat(3)(원래 함수)` 형태로 풀어서 연결을 추적했다.
- 최종 통합 문제는 외부 AI 도움을 받아 완성하고, 실행 결과를 확인했다.

---

## 아직 모르는 점 (다음에 다시 검증)

- 요구사항만 보고 인수 있는 decorator 구조를 처음부터 설계하는 것 → 아직 어렵다.
- 여러 기능이 섞인 문제에서 필요한 함수와 데이터 흐름을 스스로 나누는 것 → 부족하다.
- 최종 통합 문제 독립 재현 → 실패했다. 외부 AI 도움을 받아 완성했으므로 독립 성공으로 처리하지 않는다.
