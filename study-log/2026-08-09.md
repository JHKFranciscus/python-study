# 학습 일지 — 5주차 복습 및 통합 재현

## 오늘의 결론

개념 하나짜리 문제는 어느 정도 풀 수 있었지만, 여러 개념을 한 프로그램으로 조합하는 단계에서 막혔다.
주된 원인은 개별 문법 자체보다, 변수에 무엇이 들어 있는지와 데이터 구조를 추적하고 여러 문법을 연결하는 과정에 있었다.

---

## 오늘 한 것

1. 5주차 전체 복습
   - `enumerate`, `zip`, comprehension
   - iterable / iterator / generator
   - 함수 객체, `map`, `filter`, decorator
   - `dataclass`, `field`
   - module / package / import
   - 가상환경, `requirements.txt`, `pathlib`
2. 예상 결과를 먼저 쓴 뒤 실제 실행 결과와 비교했다.
3. 5주차 내용을 조합한 프로그램을 독립적으로 재현해 보려 했다.
4. 재현에 실패한 부분은 작은 문제로 나누어 다시 확인했다.

---

## 막힌 점 → 다시 확인한 것

**1) 컬렉션과 요소를 구분하지 못했다**
- 막힌 점: 여러 객체가 들어 있는 `records`와 객체 하나인 `record`의 역할을 구분하지 못해 `records.minutes`처럼 접근했다.
- 다시 확인: `Product` 예제로 분리해 `products → product → product.price` 순서를 판단한 뒤, generator를 직접 작성했다.

**2) 값이 필요한지 함수가 필요한지 판단하지 못했다**
- 막힌 점: `map()`을 쓸 때 그 자리에 값이 필요한지 함수가 필요한지를 코드 작성 중에 판단하지 못했다.
- 다시 확인: `map(lambda product: product.name, products)`를 직접 작성했다.

**3) decorator에서 인수를 연결하지 못했다**
- 막힌 점: 인수를 받는 함수에 decorator를 적용할 때 `wrapper`와 원래 함수의 인수를 연결하지 못했다.
- 다시 확인: 단계적인 설명을 받은 뒤 `wrapper(products) → func(products) → 반환값 보존` 구조를 작성하고 실행 결과를 확인했다.
- 단, 설명을 받고 쓴 것이므로 독립 재현으로 처리하지 않았다.

**4) 일부 개념을 정확한 기준으로 설명하지 못했다**
- 막힌 점: module/package와 `pathlib` 일부 개념을 정확한 기준으로 설명하지 못했다.
- 다시 확인: `calculator`가 package임은 확인할 수 있지만 최상위 `project`가 package인지는 주어진 정보만으로 확정할 수 없음을 정리했다. `Path`의 `/`, `name`, `suffix`, `parent` 결과도 직접 실행해 확인했다.

---

## 기록 기준

- 독립 재현에 실패한 뒤 정답을 보고 고친 부분은 **독립 성공으로 처리하지 않았다.**

---

## 배운 점

- 코드를 쓰기 전에 매개변수로 무엇이 들어오는지, 하나인지 여러 개인지 먼저 확인해야 한다.
- 여러 데이터가 들어 있다면 collection 자체와 거기서 꺼낸 요소 하나를 구분해야 한다.
- 함수를 쓸 때는 지금 이 자리에 값이 필요한지 함수가 필요한지 확인해야 한다.
- 문법을 기억하는 것과, 여러 문법을 연결해 프로그램을 독립적으로 작성하는 것은 별개의 능력이다.

---

## 아직 모르는 것

- 새로운 문제에서도 별도 안내 없이 변수의 역할과 데이터 구조를 스스로 추적할 수 있는지 확실하지 않다.
- 인수를 받는 함수의 decorator 구조는 도움을 받은 뒤 작성했기 때문에, 아직 독립 재현이 가능하다고 볼 수 없다.
- 여러 개념을 동시에 써야 할 때 코드 구조를 처음부터 설계하는 능력이 부족하다.

  1. 하나인가, 여러 개인가
