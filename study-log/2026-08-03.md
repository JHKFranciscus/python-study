# 2026-08-03 공부일지

## 한 줄 요약
`enumerate()`, `zip()`, 컴프리헨션으로 주문·대여·공부 시간 데이터를 처리했고, 조건을 잘못 재사용한 실수와 반복 변수에 대입해도 원본 리스트는 바뀌지 않는다는 점을 확인했다.

## 오늘 한 일
- `enumerate()`를 사용해 번호와 값을 함께 순회했다.
- `zip()`으로 여러 리스트의 같은 위치에 있는 값을 하나의 묶음으로 처리했다.
- 리스트 컴프리헨션으로 값 변환, 조건 필터링, 필터링 후 변환을 수행했다.
- 딕셔너리 컴프리헨션으로 과목별 공부 시간과 조건별 과목 데이터를 만들었다.
- 주문 데이터에서 주문별 금액, 결제 완료 주문, 고액 결제 주문과 결제 완료 매출을 계산했다.
- 대여 데이터에서 대여료, 미반납 물품, 고액 반납 완료 물품과 미반납 대여료 합계를 계산했다.
- 같은 컴프리헨션 구조를 주문, 대여, 공부 시간처럼 서로 다른 데이터에 반복해서 적용했다.
- 인덱스 순회, 값 중심 순회, `enumerate()` 순회의 사용 기준을 비교했다.
- SSAFY 문제 풀이는 개인적으로 완료했다.

## 막힌 부분과 해결 과정

### 1. `enumerate(zip(...))`의 값을 어떻게 나눠 받을지 바로 판단하지 못했다
- **막힌 점**: `enumerate()`와 `zip()`을 함께 사용할 때, 번호와 `zip()`이 만든 튜플을 어떤 형태로 받아야 하는지 바로 판단하지 못했다.
- **시도**: 결과를 먼저 `번호`와 `주문 정보 묶음`으로 나누고, 괄호 안에서 주문 정보를 다시 여러 변수로 언패킹했다.
- **정리**: `enumerate(zip(...))`은 바깥에서 번호와 튜플을 나누고, 안쪽에서 그 튜플을 다시 나누는 중첩 언패킹이다.

### 2. `if`와 `elif`에 같은 조건을 써서 미반납 물품까지 `반납 완료`로 출력됐다
- **막힌 점**: 대여 상태를 출력하는 조건문에서 `if`와 `elif`에 같은 조건을 작성했다.
- **시도**: 반납 여부가 참이면 `반납 완료`, 거짓이면 `else`에서 `미반납`이 되도록 조건문을 수정했다.
- **정리**: 같은 조건을 두 번 쓰면 `elif`는 실행될 수 없다. 참과 거짓 두 갈래로 나뉘는 경우는 `else`로 받는다.

### 3. 미반납 대여료 문제에 직전 문제의 조건을 그대로 사용했다
- **막힌 점**: 미반납 대여료를 구하는 문제에서 직전 문제의 `반납 완료이면서 25000원 이상` 조건을 그대로 사용했다.
- **시도**: 미반납 자료만 선택하도록 조건을 `if not is_returned`로 바꿨다.
- **정리**: 같은 데이터로 이어지는 문제일수록 앞 문제의 조건을 지우고, 지금 문제가 요구하는 조건부터 다시 확인해야 한다.

### 4. 반복 변수에 값을 대입하면 원본 리스트도 바뀔 것으로 예상했다
- **막힌 점**: 반복 변수에 두 배의 값을 대입하면 원본 리스트도 바뀔 것으로 예상했다.
- **시도**: 반복 변수만 변경한 경우와 `numbers[index]`에 직접 값을 저장한 경우의 실제 출력을 비교했다.
- **정리**: 반복 변수에 대입했을 때는 원본 리스트가 바뀌지 않았고, `numbers[index]`에 저장했을 때만 바뀌었다. 예상과 실제가 달랐던 부분이라 차이와 원인을 따로 기록했다.

## 알게 된 점

**순회 도구**
- `enumerate()`는 번호와 값을 함께 제공하며, 시작 번호는 `start`로 지정할 수 있다.
- `zip()`은 여러 자료의 같은 위치에 있는 값을 묶고, 가장 짧은 자료의 길이까지만 값을 제공한다.
- `enumerate(zip(...))`에서는 번호와 내부 튜플을 중첩 언패킹할 수 있다.
- 값을 읽기만 할 때는 값 중심 순회, 번호와 값이 모두 필요할 때는 `enumerate()`, 원본 위치를 직접 수정할 때는 인덱스 순회가 적절하다.

**컴프리헨션**
- 리스트 컴프리헨션과 딕셔너리 컴프리헨션은 원본을 수정하지 않고 새로운 자료를 만든다.
- 컴프리헨션의 `if`는 결과에 포함할 항목을 선택하며, 조건을 통과한 값에만 변환식이 적용된다.

**값 변경과 원본**
- `for value in list`에서 `value`에 새 값을 대입하면 반복 변수가 가리키는 대상만 바뀌고 리스트 내부의 값은 바뀌지 않는다.
- 원본 리스트를 수정하려면 `list[index]`에 직접 새로운 값을 저장해야 한다.

**공부 방법**
- 예상 결과는 틀렸더라도 실제 결과에 맞춰 고치지 않고, 두 결과의 차이와 원인을 별도로 기록해야 한다.

## 아직 모르는 것
- `zip()`과 `enumerate()`가 내부적으로 값을 하나씩 제공하는 과정은 아직 설명할 수 없다.
- iterable과 iterator가 정확히 어떻게 구분되는지 모른다.
- 컴프리헨션의 처리 내용이 복잡해졌을 때 일반 반복문으로 바꿔야 하는 판단 기준은 더 연습해야 한다.

## 내일 할 일
- iterable과 iterator의 차이를 학습한다.
- `iter()`와 `next()`로 값이 하나씩 제공되는 과정을 확인한다.
- generator와 `yield`의 기본 동작을 새로운 데이터 문제에 적용한다.
