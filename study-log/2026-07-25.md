## 시도한 것

- 발생한 예외와 except에 지정한 예외를 일부러 다르게 써서 실행했다. → 예외가 처리되지 않고 traceback이 출력되면서 프로그램이 종료됐다.
- 가격에 abc, -100, 8000, 3.5를 입력해 두 방식을 비교했다. → isdigit()은 abc, -100, 3.5를 모두 걸러냈지만, int()는 -100을 정상 변환해서 음수 검사를 따로 해야 했다.
- JSON 파일을 백업한 뒤 내용을 `[`로 손상시켜 실행했다. → json.JSONDecodeError가 잡혀 빈 목록으로 시작했고 프로그램은 종료되지 않았다.
- 프로그램을 종료하고 다시 실행했다. → JSON에 저장된 도서가 그대로 남아 있었다.

## 막힌 부분

- return으로 값을 돌려주는 것과 예외가 바깥으로 전달되는 것이 어떻게 다른지 바로 구분되지 않았다.
- 같은 try의 except로 넘어가는 것도 예외 전파라고 부르는지 헷갈렸다.
- json.load()가 파일 내용을 읽어서 Python 객체로 바꾸는 중간 과정이 잘 그려지지 않았다.
- main과 service에 조회 코드가 중복되어 있어 역할을 어디까지 나눠야 할지 판단이 어려웠다.
- SSAFY 문제에서 다이나믹 프로그래밍 유형을 가장 많이 틀렸다.

## 배운 점

- return은 함수를 정상적으로 끝내고 결과를 돌려주지만, 예외는 함수가 결과를 돌려주지 못한 채 호출한 쪽으로 넘어간다.
- 같은 try에 붙은 except가 바로 처리하는 것은 예외 처리, 현재 범위에서 처리되지 못해 바깥으로 넘어가는 것은 예외 전파라고 한다.
- FileNotFoundError는 open()에서, json.JSONDecodeError는 json.load()가 파일 내용을 해석하는 과정에서 발생한다.
- isdigit()은 문자 구성만 보고, try-except는 int() 변환이 되는지를 본다. 기준이 달라서 -100처럼 한쪽만 통과하는 값이 생기고, try-except를 쓰면 음수 검사를 따로 붙여야 한다.
- load_books가 오류 상황에서도 []를 반환하면, 호출하는 쪽에서 반환값을 항상 list로 보고 쓸 수 있다.
- try 범위는 예외가 발생할 수 있는 코드만 감싸는 것이 좋다. 범위가 넓으면 어느 줄에서 난 예외인지 알기 어렵고, 잡을 생각이 없던 예외까지 같이 잡힌다.
- main은 입력과 함수 호출, service는 기능 처리, storage는 파일 처리를 맡도록 나누면 같은 코드가 두 곳에 생기는 것을 줄일 수 있다.
