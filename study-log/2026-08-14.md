## 막힌 점

1. **class 이름** — `class="Bootstrap Card"`라고 작성해 Bootstrap의 실제 `card` class가 적용되지 않았다.
2. **CSS 적용 대상** — 입력 영역 전체에 적용해야 할 CSS를 개별 `<input>`에 적용했다.
3. **Flexbox 배치** — 카드와 입력 폼의 높이가 의도와 다르게 같아졌다.
4. **예외 처리** — 평균 문제에서 `count == 0`은 검사했지만, 그 아래 평균 계산이 그대로 실행되도록 작성했다.
5. **문제 조건 확인** — 두 번째 문제에 이전 문제의 조건값 `25`를 그대로 남겼고, 평균이 존재하지 않을 때도 이후 코드가 실행될 수 있는 구조로 작성했다.

## 시도한 것 *(번호는 막힌 점과 같다)*

1. `form-control` 적용 전후와 `card-body` 제거 전후를 브라우저에서 직접 비교해 각 Bootstrap class의 역할을 확인했다.
2. 꾸밀 대상이 개별 입력창인지 입력 영역 전체인지 다시 확인하고, CSS class를 부모 `<div>`로 옮겼다.
3. 높이가 같아지는 이유를 주축·교차축 기준으로 판단하고 `align-items-start`를 적용했다.
4. `count == 0`일 때 평균 계산을 하지 않도록, 계산 코드를 `else` 내부로 옮겼다.
5. 두 번째 문제의 조건을 다시 확인해 `25`를 `70`으로 수정하고, 평균이 만들어진 경우에만 이후 반복이 실행되도록 구조를 고쳤다.

## 배운 점

**HTML / CSS**

- HTML은 구조와 기능을 만들고, Bootstrap class는 그 요소에 미리 정의된 스타일을 적용한다.
- Bootstrap을 사용해도 필요한 부분은 직접 CSS로 수정할 수 있다.
- 여러 요소를 한꺼번에 배치하거나 꾸미려면, 그 요소들을 포함하는 부모를 하나의 대상으로 잡아야 한다.
  - 배치는 **배치 대상 → 직접 부모 → 그 부모에 Flexbox 적용** 순서로 판단한다.

**알고리즘**

- 평균처럼 나눗셈이 필요한 계산에서는 분모가 0이 될 가능성을 먼저 확인해야 한다.
- 뒤에서 사용할 기준값이 먼저 필요하다면, 첫 번째 반복에서 기준값을 만든 뒤 두 번째 반복에서 사용할 수 있다.

**CS**

- Layout은 요소의 크기와 위치를 계산하고, Paint는 실제 화면에 그리는 단계다.

## 아직 부족한 부분

- Bootstrap의 정확한 class 이름을 요구사항에서 빠뜨리지 않는 연습이 필요하다.
- CSS를 작성하기 전에 실제로 꾸미려는 대상이 어느 요소인지 판단하는 정확도를 더 높여야 한다.
- 알고리즘에서는 예외 조건을 처리한 뒤, 아래 코드가 계속 실행되는지도 확인해야 한다.
- 이전 문제의 숫자나 조건을 새 문제에 남겨두지 않도록 문제 조건을 다시 확인하는 습관이 필요하다.

## 내일

- 새로운 HTML/CSS 구조에서도 먼저 요소의 관계와 직접 부모를 파악한 뒤 배치와 스타일을 적용한다.
- 알고리즘은 코드 작성 전에 `조건 → 필요한 누적값 → 계산 시점 → 예외 상황`을 먼저 확인한다.
