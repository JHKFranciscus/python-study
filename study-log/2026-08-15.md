## 막힌 부분과 해결 과정

### 1. `transition`과 `animation`을 혼동했다
- **막힌 부분**: hover의 `transform`도 `@keyframes`에서 정의해야 한다고 생각했다.
- **시도**: 기본 selector에는 `transition`, 변화가 발생하는 `:hover`에는 `transform`을 작성하고 실제 동작을 확인했다.
- **결과**: `transition`은 두 상태 사이의 property 변화에 시간을 주고, `animation`은 `@keyframes`로 여러 변화 단계를 정의해 실행한다는 차이를 구분하게 되었다.

### 2. `transition`을 `:hover`에 작성했다
- **막힌 부분**: 커서를 뗄 때의 변화까지 고려하지 못했다.
- **시도**: `transition`을 기본 selector로 옮기고, 커서를 올릴 때와 뗄 때의 동작을 모두 확인했다.
- **결과**: hover 진입과 해제 양쪽의 변화에 transition을 적용하려면 기본 selector에 작성하는 것이 적절하다.

### 3. 요소가 '의미'용인지 '배치'용인지 구분하지 못했다
- **막힌 부분**: 의미 있는 문서 구역인 `<section>`과 단순 배치용 `<div>`의 역할을 한 번 혼동했다.
- **시도**: CSS나 Flexbox를 적용하기 전에 꾸밀 대상과 배치할 대상을 먼저 찾고, 배치의 경우 직접 부모를 확인했다.
- **결과**: 태그는 의미 기준(`<section>`)과 배치 기준(`<div>`)으로 나누어 선택하고, Flexbox는 배치할 요소의 직접 부모에 적용하는 기준을 세웠다.

### 세운 기준을 두 번 검증했다
- 통합 페이지를 완성한 뒤 요구사항을 변경해, 같은 판단 기준으로 기존 구조를 수정했다.
- 최종 독립 재현에서는 이전 완성 코드를 보지 않고 HTML 구조, Flexbox 적용 위치, 공통 class를 직접 결정했다.

## 배운 점
- `transition`은 두 상태 사이의 property 변화에 시간을 주고, `animation`은 `@keyframes`로 여러 변화 단계를 정의해 실행한다.
- Flexbox는 **배치할 요소를 찾고 → 그 요소들의 직접 부모를 찾는** 순서로 판단할 수 있다.
- Bootstrap으로 기본 디자인과 배치를 만들고, 필요한 부분만 직접 CSS로 수정할 수 있다.
- 반복되는 디자인은 공통 class로 묶어 적용할 수 있다.
- 최댓값을 찾을 때 실제 데이터의 값을 최초 후보로 사용하고, 값과 index를 함께 갱신하면 위치도 추적할 수 있다.
- 크기·위치가 변하면 Reflow가 필요하고, Layout 변화 없이 보이는 모습만 변하면 Repaint가 필요하다.

## 아직 부족한 부분
- `transition`과 `animation`은 처음에 혼동했으므로, 처음 보는 상황에서도 바로 구분되는지 복습이 필요하다.
- 기본적인 페이지 구조와 배치는 독립적으로 만들 수 있지만, 복잡한 레이아웃과 세부 디자인 경험은 아직 부족하다.
- semantic tag와 단순 배치용 요소를 의미에 따라 선택하는 연습이 더 필요하다.

## 면접용 3줄 정리
- **`transition` vs `animation`**: 두 상태 사이의 변화에 시간을 주면 `transition`, `@keyframes`로 여러 단계를 정의해 실행하면 `animation`이다. `transition`은 기본 상태에 작성해야 양쪽 방향 모두 적용된다.
- **Flexbox 적용 위치**: 배치할 요소를 먼저 찾고 → 그 요소들의 직접 부모에 적용한다.
- **Reflow vs Repaint**: 크기·위치가 변하면 Reflow, Layout 변화 없이 보이는 모습만 변하면 Repaint가 필요하다.
