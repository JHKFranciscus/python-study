## 막힌 점 → 시도한 것 → 배운 점

> 번호가 서로 대응한다. 1번 막힌 점 = 1번 시도 = 1번 배운 점.

### 막힌 점

1. Ubuntu 26.04와 MongoDB 설치 환경을 분리하는 과정에서 오래 막혔다. `mongod`와 `mongosh`의 역할 및 실행 환경도 처음에 명확히 구분하지 못했다.
2. `insertMany()`에서 여러 document를 배열 하나로 전달해야 한다는 구조에서 반복해서 오류가 났다.
3. `Collection → find() → Cursor → document 하나`의 관계를 바로 구분하지 못했다.
4. PyMongo 저장 결과에서 `_id`를 다시 사용하는 과정에서 `inserted_id` / `inserted_ids` 연결이 바로 되지 않았다.
5. 독립재현에서 처음부터 코드가 써지지 않았다. `from pymongo import MongoClient` 한 줄과 데이터 부분까지 쓰고 더 진행하지 못했다.

### 시도한 것

1. MongoDB Server는 Ubuntu 24.04에서 실행하고, 기존 Ubuntu 26.04 개발 환경에서는 `mongosh`와 PyMongo를 사용하는 구조로 구성했다.
2. `insertMany()` 오류를 수정하면서 `{}`는 document 하나, `[]`는 여러 document를 묶는 배열이라는 차이를 확인했다.
3. `find()`과 `findOne()`을 직접 비교해 Cursor와 document 하나의 차이를 확인했다.
4. 같은 `_id` 문자열을 문자열 그대로 조회했을 때와 `ObjectId`로 조회했을 때 결과를 비교했다.
5. 막힌 부분은 교정받은 뒤 직접 수정해 전체 Create/Read 흐름을 완성했다.

### 배운 점

1. 실제 데이터 검색은 MongoDB 서버가 수행하며, PyMongo는 Python과 MongoDB 사이의 드라이버 역할을 한다.
2. `insert_one()`은 document 하나를 받고, `insert_many()`는 여러 document가 들어 있는 list를 받는다.
3. `find_one()`은 document 하나 또는 `None`을, `find()`는 여러 결과를 순회할 수 있는 Cursor를 반환한다. Cursor를 `for`로 순회하면 반복 변수에는 document 하나가 들어간다.
4. 저장 메서드의 반환값을 받아두면 `inserted_id` 또는 `inserted_ids`로 생성된 `_id`를 이후 작업에 사용할 수 있다.
5. `MongoClient → Database → Collection → document` 순서로 객체와 데이터를 추적해야 한다.

## 그 외 배운 점

- Python list/dict는 실행 중인 프로세스 메모리에 존재하지만, MongoDB는 데이터를 프로그램 실행과 분리해 지속적으로 저장한다.
- DB에 저장이 성공했다고 데이터의 의미까지 올바른 것은 아니다.
- 연속된 반복문은 시간복잡도를 곱하는 것이 아니라 더한다. 이번 빈도수 문제는 최종적으로 `O(n)`이다.
- 영구 저장과 백업은 서로 다른 개념이다.
