## 오늘 한 일
- 캡슐화의 목적과 getter·setter의 역할을 학습했다.
- 값은 `_price`에 저장하고, `price`로 읽으면 getter가, `price`에 값을 대입하면 setter가 실행되는 구조를 확인했다.
- setter에 가격의 자료형과 범위 검증을 넣어 문자열과 음수가 저장되지 않도록 했다.
- 생성자에서도 `self.price = price`를 사용해, 객체를 만드는 시점부터 같은 검증을 거치게 했다.
- 자식 클래스 `DownloadProduct`가 부모 `Product`의 getter·setter를 그대로 상속하는 것을 확인했다.
- 검증을 통과한 객체를 JSON으로 저장하고, 다시 실제 클래스의 객체로 복원했다.
- JSON 기반 상품 관리 프로그램을 요구사항만 보고 독립 재현한 뒤 검색·가격 변경·삭제·저장을 확인했다.
- 직접 속성 변경, 변경 메서드, property setter 세 가지 방식의 차이를 비교했다.
- SSAFY 학습과 객체의 유효한 상태·데이터 무결성에 관한 CS 학습을 완료했다.

## 막힌 부분
- `self.price`가 값을 저장하는 속성인지, getter·setter를 부르는 이름인지 처음에는 구분하지 못했다.
- 같은 `price`라도 읽을 때는 getter가, 대입문 왼쪽에 올 때는 setter가 실행된다는 차이를 혼동했다.
- 독립 재현에서 `ProductManager`가 스스로 파일을 읽어 복원해야 한다는 역할을 놓치고, 생성자가 외부 목록을 받도록 작성했다.
- `load_products()`의 `return` 위치를 잘못 잡았고, 기존 목록과 복원 목록도 구분하지 못해, 복원된 객체가 아니라 기존 객체를 확인하고 있었다.

## 시도한 것
- getter만 있는 클래스와 getter·setter가 모두 있는 클래스를 따로 만들어 조회와 대입 결과를 비교했다.
- 정상 가격, 문자열, 음수를 차례로 대입해 setter가 실행되는지, 대입이 막혔을 때 기존 값이 유지되는지 확인했다.
- JSON으로 저장한 뒤 새 `ProductManager`를 만들어 복원된 객체의 클래스와 가격, 저장된 파일의 크기를 확인했다.
- 독립 재현 코드에서 생성자의 역할, 반복문 밖의 반환 위치, 새 관리자 사용 여부를 하나씩 고친 뒤 처음부터 다시 실행했다.
- 직접 속성 변경, 변경 메서드, property setter 세 방식을 같은 조건으로 실행해 검증을 우회할 수 있는 경로를 비교했다.

## 배운 점
- getter는 내부 값을 밖으로 돌려주고, setter는 받은 값을 검사한 뒤 내부 속성에 저장한다.
- `price`는 값을 따로 담는 속성이 아니라 `_price`로 가는 관리된 통로다.
- 생성자에서 `self.price = price`를 쓰면 최초 값도 setter를 거치지만, `self._price = price`는 검증을 건너뛴다.
- 자식 클래스는 부모의 getter·setter를 상속받으며, 부모 생성자를 호출해야 `_price`도 초기화된다.
- JSON 문법이 맞다고 해서 그 안에 든 상품 값까지 유효한 것은 아니다.
- 생성·변경·복원이 모두 같은 setter를 지나가면 검증 규칙을 한곳에서 관리할 수 있고 데이터 무결성이 유지된다.
- 독립 재현에서는 기능이 동작하는지뿐만 아니라, 각 클래스와 함수가 맡는 역할,
값을 반환하는 시점, 실제로 확인하는 대상까지 구분해야 한다.

## 아직 모르는 점
- 정상 상품과 잘못된 상품이 함께 들어 있는 JSON에서, 프로그램을 종료하지 않고 잘못된 상품만 빼고 복원하는 방법은 아직 직접 구현해 보지 않았다.
- `_price`의 밑줄은 내부용이라는 관례일 뿐이라, 외부에서의 직접 접근을 더 강하게 막는 방법은 아직 학습하지 않았다.
