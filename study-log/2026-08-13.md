# 6주차 4일차 공부일지

**오늘의 키워드**
Flexbox 적용 위치 판단 / Bootstrap·직접 CSS 역할 분담 / 독립 재현 / 조건 경계값 확인

> 한 줄 요약: Bootstrap으로 배치하고 직접 CSS로 디자인한 카드 페이지를 만든 뒤, 같은 화면을 보지 않고 독립 재현했다.

---

## 오늘 한 일

- Bootstrap을 CDN으로 연결하고 `btn`, `d-flex`, `gap`, `justify-content-*`, `align-items-center` class를 사용했다.
- 배치는 Bootstrap이, 카드 디자인은 직접 작성한 CSS가 담당하도록 역할을 나눴다.
- `border-radius`, `box-shadow`를 사용해 카드 디자인을 수정했다.
- `:hover`와 `transition`으로 배경색·글자색이 부드럽게 변하는 효과를 구현했다.
- 실제 공부 기록 페이지와 별도로 독립 재현 페이지를 만들었다.
- 알고리즘에서 조건을 만족하는 값의 합과 개수를 동시에 누적했다.
- HTML → DOM, CSS 해석 → 화면 표시로 이어지는 기본 흐름을 학습했다.

## 막힌 부분

- **Flexbox 적용 위치**: flex container가 class 자체인지 실제 HTML 요소인지 혼동했다.
- **CSS property 역할**: `padding: 20px white;`처럼 `padding`과 `background-color`의 역할을 섞어 썼다.
- **Bootstrap class 읽기**: `class="btn btn-danger"`를 처음에는 class 1개라고 잘못 판단했다.
- **HTML 구조**: 독립 재현에서 `<button href="#">`, `<div>` 바로 아래 `<li>` 같은 구조 오류가 있었고, `padding` 요구사항도 빠뜨렸다.
- **조건 경계값**: 알고리즘에서 `10보다 큰 값`을 `>= 10`으로 잘못 작성했다.

## 시도한 것

- 버튼을 오른쪽으로 옮길 때 버튼 자체가 아니라 버튼의 직접 부모를 flex container로 만들었다.
- `gap`과 `justify-content-evenly`를 각각 적용해 두 배치 방식의 차이를 직접 확인했다.
- 독립 재현에서는 이전 페이지를 보지 않고 중첩 Flexbox, Bootstrap 버튼, 직접 CSS, `:hover`/`transition`을 연결해 구현했다.
- 알고리즘에서는 합을 저장하는 변수와 개수를 저장하는 변수를 따로 두고 동시에 갱신했다.

## 배운 점

- flex container는 class 이름이 아니라 `display: flex`가 적용된 실제 HTML 요소다.
- 배치 대상 → 직접 부모 → flex container 순서로 판단하면 Flexbox를 적용할 위치를 찾을 수 있다.
- `gap`은 item 사이에 정해진 간격을 만들고, `justify-content-evenly`는 남는 공간을 전체에 균등하게 나눈다.
- Bootstrap은 기존 CSS 개념을 미리 만들어진 class로 쓸 수 있게 해준다. 필요한 부분만 Bootstrap으로 처리하고 나머지는 직접 CSS로 작성할 수 있다.
- `margin`은 요소 바깥, `padding`은 요소 경계와 내부 내용 사이의 공간이다.
- `:hover`는 상태에 따른 값, `transition`은 값이 변하는 과정을 담당한다.
- 알고리즘에서 `total += 현재 값`과 `count += 1`은 역할이 다르며, `>`와 `>=` 같은 경계값도 정확히 확인해야 한다.

## 아직 부족한 부분

- HTML tag와 attribute의 올바른 조합을 더 익혀야 한다.
- 독립 재현에서 핵심 구조는 직접 구현했지만 세부 요구사항을 한 번에 모두 확인하지 못했다.
- CSS 간격·배치 property를 상황에 맞게 선택하는 판단을 더 반복해야 한다.
- 알고리즘은 구조보다 문제의 조건을 정확하게 옮기는 마지막 검사가 필요하다.
