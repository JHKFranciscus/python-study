## 오늘 한 일
- 클래스, 객체, 인스턴스의 관계를 학습했다.
- `Book()`을 여러 번 호출하면 서로 다른 인스턴스가 만들어진다는 것을 `is`와 객체 주소로 확인했다.
- `__init__`과 `self`를 사용해 제목, 저자, 가격, 출판 연도를 인스턴스 속성으로 저장했다.
- 객체 주소를 출력해 `self`와 인스턴스 변수가 같은 객체를 가리키는지 비교했다.
- `show_info`, `change_price`, `increase_price` 인스턴스 메서드를 작성했다.
- `Book` 인스턴스를 리스트에 저장하고 등록, 전체 조회, 제목 검색, 가격 변경 기능을 구현했다.
- `is`와 `==`의 차이를 확인하고, `__eq__`로 객체의 동등성 비교 기준을 직접 정의했다.
- 클래스 기반 도서 관리 프로그램을 코드를 보지 않고 처음부터 다시 구현했다.
- 빈 목록 조회와 잘못된 가격 입력 상황을 직접 테스트했다.

## 막힌 부분
- 처음에는 속성이 `int`, `str` 같은 타입을 뜻하는 것인지 헷갈렸다.
- `add_book` 함수를 `Book` 클래스 안에 들여쓴 채로 두고 클래스 밖에서 호출해 `NameError`가 발생했다.
- 다시 구현할 때, `show_info`가 이미 속성으로 저장된 `title`, `author`, `price`를 매개변수로 또 받도록 작성했다.
- 검색에 성공했을 때 `print(found)`를 써서 책 정보가 아니라 객체 주소가 출력됐다.
- 가격을 `int(input())`이 아니라 `input()`으로만 받아서 문자열로 저장됐다. 입력할 때 숫자만 써서 바로 티가 나지 않았고, 나중에야 알아챘다.
- 반환값이 없는 함수는 자동으로 `None`을 반환하기 때문에, 책이 있어도 `"책이 없습니다."`가 출력됐다.
- `int()`를 적용한 뒤, 가격에 `"삼만오천"`을 입력했을 때 `ValueError`가 발생했다.

## 시도한 것
- `add_book`의 들여쓰기를 풀어 클래스 밖으로 옮겼다.
- `show_info`의 매개변수를 `self`만 남기고, 속성은 `self`로 접근하도록 수정했다.
- `print(found)` 대신 `found.show_info()`를 호출했다.
- 가격 입력에 `int()`를 적용했다.
- `show_all_books`가 빈 목록이면 `False`, 책이 있으면 `True`를 반환하도록 수정했다.
- `try-except ValueError`를 사용해, 잘못된 가격을 입력한 뒤에도 프로그램이 계속 실행되게 했다.

## 배운 점
- 속성은 객체에 저장된 이름 있는 데이터이고, 타입은 그 속성에 담긴 값의 종류다.
- `self`는 모든 인스턴스를 한꺼번에 뜻하는 것이 아니라, 지금 메서드를 실행 중인 인스턴스 하나를 가리킨다.
- 같은 클래스로 만든 객체라도 인스턴스 속성은 각각 따로 가진다.
- 함수나 메서드 안에서 원본 객체의 속성을 변경하면, 호출이 끝난 뒤에도 변경이 남는다.
- `is`는 같은 객체인지 확인하고, `==`는 정의된 비교 기준으로 값이 같은지 확인한다.
- 사용자 정의 객체는 `__eq__`를 정의해 `==`의 기준을 직접 정할 수 있다.
- 함수가 별도의 값을 반환하지 않으면, 정상 실행됐더라도 `None`이 반환된다.
- `input()`의 결과는 문자열이므로, 숫자로 쓸 때는 변환과 예외 처리가 필요하다.
