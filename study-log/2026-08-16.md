## 막힌 부분

- **Flexbox를 적용할 위치**: Flexbox의 정의는 알고 있었지만, 처음에는 배치하려는 요소 **자체**에 `display: flex`를 적용하려는 경우가 있었다.
- **변화 대상 선택**: 버튼 자체가 커져야 하는 문제에서 처음에는 `.card:hover`를 선택하는 등, 실제로 변화해야 하는 요소를 정확히 고르는 판단이 흔들렸다.
- **종합 구현**: 작업 이름과 버튼을 양쪽에 배치할 때 `gap`을 사용했고, 단순 작업 이름에 `<label>`을 사용하는 문제도 있었다.

## 시도한 것

- 배치 문제에서는 배치하려는 요소들을 먼저 확인하고, 그 요소들의 **직접 부모**를 다시 찾았다.
- 종합 구현에서는 피드백으로 발견한 문제를 정답 코드를 그대로 옮기지 않고, `justify-content` / HTML element / 중복 `id` / animation 시작값을 **직접 수정**했다.
- 화면에서 요소의 범위를 판단하기 어려울 때는 `border`를 적용해 실제 영역을 확인했다.

## 배운 것

### 1. CSS 적용 대상을 판단하는 기준

- 여러 요소를 **배치**한다 → 그 요소들의 **직접 부모**를 찾는다.
- 특정 요소 **자체가 변한다** → 그 **요소 자체**를 선택한다.

따라서 CSS부터 바로 작성하기보다, 다음 순서로 판단하는 것이 필요하다.

```
요구사항 → 변화/배치 대상 → HTML 구조 → selector → CSS
```

### 2. 알고리즘

비교 대상은 `현재 점수`와 `현재까지의 최고 점수`이고, 더 큰 값을 찾으면 **최고 점수와 학생 번호를 함께 갱신**해야 한다는 것을 확인했다.

## 아직 모르는 것

- 새로운 요구사항을 처음 봤을 때, CSS를 적용할 요소를 항상 한 번에 정확하게 판단하는 수준은 아니다.
- HTML도 화면에 원하는 결과가 나오는 것뿐 아니라, element의 **의미와 역할**까지 고려해서 선택하는 연습이 더 필요하다.
- Reflow와 Repaint가 각각 발생하는 기본적인 경우는 구분하지만, Reflow 이후 브라우저의 세부 처리 과정은 아직 학습하지 않았다.
