## 막힌 부분

1. Ajax의 `response` parameter에 데이터가 들어오는 과정을, 처음에는 서버가 parameter에 값을 직접 넣어주는 것처럼 이해했다.
2. 추가 학습에서 `$()`와 `.val()`의 역할을 순간적으로 혼동해서, `$()`가 문자열을 반환한다고 잘못 설명했다.

---

## 시도한 것

1. response의 전달 과정을 다시 따라가면서 **서버 → 브라우저 → jQuery의 Ajax 처리 → success callback 호출 → argument 전달 → `response` parameter** 순서로 구분했다.
2. 문자열을 반환하는 것은 `$()`가 아니라 `.val()`이라는 점을 다시 정리했다.
3. GET에서는 `user.json`과 `products.json`을 실제로 불러왔다.
4. 독립 재현에서는 도서 번호 `0`, `1`, `2`를 입력해 서로 다른 객체가 선택되는 것을 확인했고, `stock` 값에 따라 `구매 가능`과 `품절`이 모두 정상적으로 출력되는 것도 검증했다.
5. POST에서는 `/orders`로 실제 request를 보내 `405 Method Not Allowed`가 발생하는 것을 확인했다.

## 배운 점

**1. `success`에는 함수 자체를 등록한다**
함수를 즉시 호출한 결과가 아니라, response가 준비되었을 때 실행할 callback 함수 자체를 등록해야 한다.

**2. 배열이면 한 단계를 더 거쳐야 한다**
response가 배열이라면 바로 property에 접근하는 것이 아니라 `배열 → 객체 하나 → property 값` 순서로 접근해야 한다.

**3. `data`와 `response`는 방향이 반대다**
POST의 `data`는 Client → Server로 보내는 데이터이고, `response`는 Server → Client로 돌아오는 데이터이므로 서로 같은 값이라고 생각하면 안 된다.

**4. input에서 .val()로 가져온 값은 문자열로 다룬다**
input type="number"를 사용해도 .val()로 가져온 값은 문자열이므로, 숫자로 사용할 때는 Number() 변환이 필요하다.

**5. 오류가 났다고 JavaScript가 실행되지 않은 것은 아니다**
`405`를 통해, 이번 경우에는 POST request가 서버까지 도착했지만 서버가 해당 method를 처리하지 못한 상황이라는 것을 확인했다.
