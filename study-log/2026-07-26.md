## 막힌 점

- `json.dump()`와 `json.load()`의 역할을 혼동했다.
- 딕셔너리를 만들 때 `키: 값` 형태가 아니라 값만 나열하여 `set`을 만들었다.
- 파일이 없는 상황을 여러 함수에서 각각 출력해 안내 문구가 중복됐다.
- 검색 함수가 결과 목록이 아니라 `True` 또는 `False`만 반환해 `main`에서 같은 검색을 다시 수행했다.
- 가격의 정수 변환과 `ValueError` 처리를 `main`과 `service` 중 어디에서 해야 하는지 바로 구분하지 못했다.
- 가격 수정 함수를 다시 작성하면서 함수를 중복 정의하고 내부 함수 형태로 넣었다.
- JSON 시험에서 코드가 사용하는 파일명과 다른 이름의 파일을 만들어 잘못된 예외를 확인했다.

## 시도한 것

- 파일이 없는 상태, 빈 입력, `abc` 입력, 잘못된 JSON 파일을 직접 만들어 실행했다.
- 검색어와 도서 제목에 `strip()`과 `lower()`를 적용했다.
- 검색 함수가 검색된 도서 목록 자체를 반환하도록 수정했다.
- 파일 관련 예외는 `storage`에서 처리하지 않고 `main`까지 전파되도록 만들었다.
- 입력값의 정수 변환과 사용자 안내는 `main`으로 옮겼다.
- 검색·추가·수정·삭제 규칙은 `service`, 파일 읽기·저장은 `storage`가 담당하도록 다시 나눴다.
- 프로그램을 종료하고 다시 실행하여 JSON 데이터가 유지되는지 확인했다.

## 배운 점

- `json.dump()`는 파이썬 객체를 JSON 파일에 저장하고, `json.load()`는 JSON 파일을 파이썬 객체로 불러온다.
- `{"topic", topic}`은 `set`이고, `{"topic": topic}`은 `dictionary`이다.
- 함수의 반환값을 먼저 정하지 않으면 호출한 쪽에서 같은 처리를 반복할 수 있다.
- 검색 함수가 결과 목록을 반환하면 `main`은 출력만 담당할 수 있다.
- 사용자 입력과 출력, 문자열의 정수 변환, 최종 오류 안내는 `main`에서 처리하는 편이 역할 구분에 맞다.
- 데이터 처리 규칙은 `service`, 파일 입출력은 `storage`가 담당한다.
- 하위 함수에서 처리하지 않은 예외는 호출 스택을 따라 상위 함수로 전파된다.
- 프로그램이 정상적으로 실행되는 것만으로는 충분하지 않고, 잘못된 입력과 파일 오류도 직접 시험해야 한다.

## 아직 모르는 것

- 프로그램을 작성하기 전에 함수의 입력값과 반환값을 빠르게 설계하는 방법이 아직 익숙하지 않다.
- 예외를 발생한 함수에서 처리할지 상위 호출자에서 처리할지 처음부터 판단하는 연습이 더 필요하다.
- 프로그램이 더 커졌을 때 `main`, `service`, `storage`보다 역할을 더 세분화하는 기준은 아직 모른다.
- 다이나믹 프로그래밍 문제에서 저장할 상태와 점화식을 찾는 것이 부족하다.
