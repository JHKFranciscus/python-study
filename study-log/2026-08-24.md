# 8주차 1일차 공부일지 — Flask 시작

**한 줄 요약**
Flask에서 request가 들어와 route를 거쳐 함수가 실행되고 response가 나가는 흐름을 처음 확인했지만, 아직 안내 없이 혼자 구현하지는 못하는 상태다.

---

## 오늘 한 일

1. **form 보완** — 이전 HTML/CSS 학습에서 빠졌던 `<form>`을 채웠다. action, method, name, submit의 역할을 확인하고 직접 form을 만들어 POST 요청을 보내봤다.
2. **Flask 설치와 첫 서버 실행** — 가상환경에 Flask를 설치하고 처음으로 서버를 실행했다.
3. **route 연결** — `@app.route()`로 URL path와 Python 함수를 연결했고, request가 들어온 뒤 연결된 함수가 실행되고 그 return 값으로 response가 만들어지는 과정을 확인했다.
4. **정적 route / 동적 route** — 정적 route와 `/books/<int:book_id>` 형태의 동적 route를 사용했고, URL의 값이 converter를 거쳐 함수 parameter로 전달되는 과정을 실습했다.
5. **한 route에 GET과 POST** — 같은 `/books`에 GET과 POST를 모두 허용한 뒤 `request.method`로 서로 다른 결과를 반환해봤다.
6. **직접 구현 + 독립 재현, 개념 정리** — routing을 직접 구현해보고 독립 재현까지 진행했다. 127.0.0.1, port, Live Server와 Flask 서버의 차이, ERR_CONNECTION_REFUSED / 404 / 405의 차이도 정리했다.

---

## 막힌 부분

설명을 하나씩 들을 때는 따라갈 수 있었지만, 여러 개념을 직접 연결해서 코드를 처음부터 작성하려고 하자 많이 막혔다.

1. **첫 번째 routing 구현** — 함수 이름을 중복해서 사용했고, 동적 route 문법과 f-string을 잘못 작성했다. `app = Flask(__name__)`을 빠뜨리거나 필요하지 않은 POST 처리를 넣기도 했다.
2. **두 번째 독립 재현** — 동적 route에서 GET과 POST를 함께 처리하는 구조를 잡지 못했고, form의 요청 경로도 제대로 연결하지 못했다.
3. **port 혼동** — Live Server의 5500번 port와 Flask의 5000번 port가 섞이면서 form의 request가 내가 생각한 서버가 아닌 곳으로 갔다. 서버를 실행하는 것과 실행 중인 서버에 request를 보내는 것도 중간에 혼동했다.

---

## 시도한 것

*(위 막힌 부분과 번호가 1:1로 대응된다)*

1. **첫 번째 구현** — 최초 시도는 실패했다. 안내받은 내용을 반영해 수정한 뒤 정적 route와 동적 route를 각각 직접 실행했고, form을 통해 POST도 실제로 보내서 동작을 확인했다.
2. **두 번째 독립 재현** — 이것도 최초 시도는 실패했지만 수정 후 최종 동작까지 확인했다. 최종 결과는 아래와 같다.

   | 요청 | 결과 |
   |---|---|
   | GET /  | Member Server |
   | GET /status | Server Running |
   | GET /members/12 | Member 12 |
   | GET /members/50 | Member 50 |
   | POST /members/12 | Member 12 Updated |
   | GET /members/hello | 404 |

   `/members/hello`가 404가 된 것은 `hello`가 int로 변환되지 않아서 그 route에 매칭되지 않았기 때문이다.

3. **오류 확인 방식** — 오류가 발생할 때마다 request의 path, method, port를 하나씩 확인하며 수정했다.

> 다만 수정 과정에서 안내받은 코드를 그대로 옮긴 부분도 많았기 때문에, 독립 구현에 성공했다고 보지는 않는다.

## 알게 된 것

**핵심: route 함수의 코드는 내가 작성하지만, 실제 request가 들어왔을 때 어떤 함수를 실행할지 판단하고 호출하는 것은 Flask다.**

현재 내가 이해한 기본 흐름은 다음과 같다.

```
브라우저가 request 생성
→ Flask가 request 수신
→ path와 method에 맞는 route 확인
→ 연결된 Python 함수 호출
→ 함수가 값 return
→ Flask가 response 생성
→ 브라우저가 response 수신
```

**1. 동적 route의 converter는 값을 전달하기만 하는 게 아니라 걸러내기도 한다**
`<int:book_id>`처럼 converter를 쓰면, int로 변환할 수 없는 값이 들어왔을 때 그 route에 매칭되지 않는다. 실제로 `GET /members/hello`가 404가 난 이유가 이것이다.

**2. methods와 request.method는 역할이 다르다**
- `methods=["GET", "POST"]` : 그 route에서 **허용할** method를 정하는 것
- `request.method` : 실제로 **들어온** request의 method를 함수 안에서 확인하는 것

**3. return은 브라우저에 직접 출력하는 것이 아니다**
return은 Flask에 값을 반환하는 것이고, 그 값을 이용해 response를 만드는 것은 Flask다.

**4. 오류는 "어디까지 갔는가"로 구분된다**

| 오류 | 상황 |
|---|---|
| ERR_CONNECTION_REFUSED | 서버와 연결 자체가 되지 않음 |
| 404 | 서버에는 도착했지만 맞는 route가 없음 |
| 405 | route는 있지만 해당 method를 허용하지 않음 |

404는 요청한 path와 최종적으로 매칭되는 route를 찾지 못했을 때 발생한다. route 규칙 자체가 없을 수도 있고, 동적 route가 있어도 converter 조건을 만족하지 못해 매칭에 실패할 수도 있다.

**5. 여러 서버가 동시에 실행될 때는 request의 목적지 host와 port도 함께 확인한다.**
이번에는 Live Server와 Flask가 서로 다른 port에서 실행되고 있었고, request가 의도한 서버가 아닌 곳으로 가는 문제가 있었다. 이후 여러 서버가 동시에 실행되는 환경에서는 request의 path와 method뿐 아니라 목적지 host와 port도 함께 확인해야 한다는 것을 알게 됐다.

## 아직 부족한 부분

오늘 배운 Flask 내용을 제대로 이해했다고 말하기는 어렵다.

- 개별 개념을 설명받으면 어느 정도 따라갈 수 있고 코드를 보고 작성할 수도 있지만, 아직 request, route, method, port, 함수 호출, response가 머릿속에서 하나의 구조로 자연스럽게 연결되지 않는다.
- **코드가 최종적으로 실행된 것과, 내가 Flask를 독립적으로 구현할 수 있다는 것은 구분해야 한다.** 실제로 직접 구현과 독립 재현 모두 최초 시도에서는 실패했고, 수정 과정에서도 안내받은 코드를 그대로 사용한 부분이 많았다.
- 지금은 전체 구조를 알고 있다기보다 각각의 조각을 처음 접한 상태에 가깝다. 이후 Flask 학습에서 같은 구조가 반복될 때, 각 코드가 전체 흐름에서 어느 위치에 있는지를 계속 확인할 필요가 있다.

## 내일

```
어떤 request인가
→ 어느 path인가
→ 어느 method인가
→ 어떤 route가 선택되는가
→ 어떤 함수가 호출되는가
→ 어떤 값이 전달되는가
→ 무엇을 return하는가
→ 어떤 response가 돌아가는가
```
