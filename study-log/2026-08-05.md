## 막힌 점
- `next()`를 호출할 때 iterator나 generator 객체가 생성된다고 잘못 판단했다.
  → 객체 생성과 `next()` 호출은 서로 다른 시점이고, `next()`는 이미 만들어진 iterator에 다음 값을 요청하는 것이다.
- 함수의 반환값이 저장된 변수를 출력할 때 함수가 다시 실행된다고 예상했다.
  → 함수는 호출할 때 한 번 실행되고, 변수에는 그 결과값만 남아 있다.
- `print()` 안에 함수 호출이나 `list()` 변환이 있을 때, 인자의 계산이 먼저 일어난다는 출력 순서를 놓쳤다.
  → 인자 안에서 나오는 출력이 먼저 찍히고, `print()`의 출력은 그 뒤에 나온다.
- 연결된 `filter()`와 `map()`이 각각 전체 처리를 마친 뒤 다음 단계로 넘어간다고 생각했다.
  → 실제로는 값을 하나씩 요청하고 넘기면서 처리한다.
- 독립 재현에서 선택한 함수 객체를 별도 변수에 저장하지 않고 `select_bonus("2")`를 다시 호출했다.
  → 반환된 함수 객체를 변수에 담아 두고 재사용해야 했다.

- `map()`과 `filter()` 결과를 `list()`로 두 번 변환해 일회성 iterator의 소진을 확인했다.
- 원본 목록과 변환 결과를 함께 출력해 원본 딕셔너리의 변경 여부를 확인했다.
- 독립 재현에서는 `selected_bonus` 변수에 함수 객체를 저장한 뒤 `map()`에 전달하도록 수정했다.

## 배운 점
- **`next()`의 대상**: iterable이라고 해서 `next()`를 직접 사용할 수 있는 것은 아니며, `next()`는 iterator에 사용한다.
- **이름과 호출의 차이**: 함수 이름만 사용하면 함수 객체를 가리키고, 괄호를 붙이면 함수가 실행되어 반환값을 얻는다.
- **함수 객체의 쓰임**: 함수 객체는 변수에 저장하거나, 인자로 전달하거나, 다른 함수의 반환값으로 사용할 수 있다.
- **고차 함수와 콜백**: 고차 함수는 전달받은 콜백을 어떤 시점에 실행할지 결정하며, 콜백이 끝나면 제어권은 호출 위치로 돌아온다.
- **`lambda`**: `lambda`도 일반 함수와 같은 함수 객체이며, 생성 시점에는 콜론 오른쪽 계산을 실행하지 않는다.
- **`filter()`와 `map()`의 역할**: `filter()`는 조건이 참인 원본 값을 그대로 통과시키고, `map()`은 전달받은 값을 새로운 값으로 변환한다.
- **연결했을 때의 처리 방식**: 연결된 `filter()`와 `map()`은 값을 하나씩 요청하고 전달하면서 처리한다.
- **재사용 여부**: `map()`과 `filter()`는 한 번 소진한 뒤 다시 `list()`로 변환해도 남은 값이 없어 `[]`가 나오며, 이미 `list()`로 저장한 결과는 반복해서 사용할 수 있다.
- **원본 보존의 이유**: 원본 상품과 점수 목록이 유지된 직접적인 이유는 원본 딕셔너리를 수정하지 않고 새로운 딕셔너리를 반환했기 때문이다.

## 아직 모르는 점

- `lambda`, `map()`, `filter()`와 리스트 컴프리헨션 중 어떤 방식을 선택할지에 대한 기준은 아직 배우지 않았다.

## 한 줄 정리
- 함수 이름은 객체를 가리키고, 괄호는 실행을 뜻한다.
- `filter()`는 고르고, `map()`은 바꾼다. 둘을 연결하면 값을 하나씩 흘려보낸다.
- `map()`과 `filter()`의 결과는 한 번 쓰면 비고, `list()`로 저장해야 남는다.
- 원본을 수정하지 않고 새 딕셔너리를 반환했기 때문에 원본 목록이 유지됐다.
- 독립 재현에서 `select_bonus("2")`를 다시 호출한 실수는, 함수 객체를 `selected_bonus` 변수에 저장하는 방식으로 고쳤다.
