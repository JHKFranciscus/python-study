# 2026-08-11 공부일지

## 한 줄 요약

HTML 문서 구조와 CSS 기본(selector, 상속, Box Model)을 배우고, 마지막에는 새 파일에서 카드 페이지를 처음부터 혼자 만들어 확인했다.

## 오늘 한 일

**HTML**

- 기본 문서 구조와 heading, 문단, 목록, 링크, `div`, `section`을 학습하고 직접 페이지에 적용했다.

**CSS**

- external CSS 연결, tag / class / id selector, specificity와 상속의 기본 동작을 실습했다.
- Box Model의 `content`, `padding`, `border`, `margin`과 `content-box` / `border-box`의 차이를 확인했다.
- `background-color`, `border-radius`, `text-align`, `margin: auto`로 카드 형태의 실제 페이지를 만들고 배치를 다듬었다.

**독립 재현**

- 새 HTML/CSS 파일을 처음부터 작성해 공통 class, 특정 id, 목록·링크 중첩, 카드 디자인을 스스로 연결했다.

**알고리즘**

- 2문제를 풀었다. 1번은 독립으로 해결했고, 2번은 조건식 오류를 안내받은 뒤 수정했다.

---

## 막힌 부분

- `title`과 heading, tag와 element, HTML attribute와 CSS property처럼 비슷하게 번역되는 용어를 구분하는 데 혼란이 있었다. 한 번 정리는 했지만 명확하게 구분하지는 못했다.
- 요구사항에 있는 class를 어느 element에 붙여야 하는지 잘못 판단해서, 카드 전체가 아니라 heading에 적용한 적이 있었다.
- `ul → li → a`처럼 이미 배운 중첩 구조를 새로운 페이지에서 바로 연결하지 못한 경우가 있었다.
- 부모에게서 상속되는 값과 자식에게 직접 지정된 값의 관계를 specificity 문제로 잘못 판단했다.
- `margin: auto`를 글자를 가운데 정렬하는 것으로 오해했다. 실제로는 고정 너비를 가진 box 자체를 좌우 가운데로 배치하는 것이었다.

---

## 시도한 것

- 코드를 작성하기 전에 각 내용이 어떤 역할인지 먼저 판단하고, 그 역할에 맞는 태그와 selector를 선택했다.
- CSS 값을 바꾸기 전에 결과를 예상한 뒤 브라우저의 실제 결과와 비교했다.
- 잘못 적용한 class와 중첩 구조는 화면 결과만 보지 않고 HTML 구조 자체를 다시 보며 수정했다.
- 마지막 재현에서는 이전 코드를 복사하지 않고 새 파일에서 처음부터 구현했다.

---

## 배운 점

- HTML은 모양보다 내용의 역할과 구조를 먼저 판단해야 한다.
- 여러 element에 공통 스타일을 적용할 때는 class, 특정 하나를 식별할 때는 id를 사용할 수 있다.
- 같은 element의 같은 property가 충돌할 때는 specificity를 확인한다. 다만 상속값과 자식에게 직접 지정된 값의 관계는 같은 방식으로 비교하지 않는다.
- `box-sizing: border-box`에서는 지정한 `width` 안에 content·padding·border가 포함되고, margin은 그 바깥에 있다.
- `margin: auto`는 고정된 width를 가진 block element에서 좌우 margin을 auto로 지정하면 남는 공간을 좌우가 나눠 가져 box 자체를 가운데 배치할 수 있다.
- 브라우저 화면이 정상으로 보여도 HTML 구조가 올바르다는 보장은 없으므로 코드 구조도 확인해야 한다.

## 아직 부족한 부분

- 비슷하게 번역되는 용어(`title`/heading, tag/element, HTML attribute/CSS property)를 스스로 설명할 수 있을 정도로는 정리하지 못했다.
- 요구사항을 읽고 class/id와 태그 중첩 위치를 한 번에 결정하는 판단은 더 연습이 필요하다.
- CSS specificity와 상속의 적용 조건을 즉시 구분할 정도로는 아직 굳히지 못했다.
- 현재는 세로 방향의 기본 카드 페이지 수준이고, 여러 element를 원하는 위치에 배치하는 레이아웃은 아직 배우지 않았다.
- 알고리즘에서는 조건식의 왼쪽과 오른쪽이 실제로 무엇을 비교하는지 작성 후 검증하는 습관이 필요하다.
