# 2026-08-08 공부일지 — 5주차 6일차

**한 줄 요약:** `dataclass`, 패키지 import, 가상환경, `pathlib`을 각각 실습한 뒤, 이 개념들을 합쳐 학습 기록을 실제 파일로 저장하는 프로그램을 완성했다.

## 오늘 한 일
- **dataclass** — field와 객체 attribute의 관계를 복습하고 `default_factory`, `repr`, `compare` 옵션을 확인했다.
- **모듈과 패키지** — 모듈 import, `__name__ == "__main__"`, 패키지와 `__init__.py`, 상대 import를 실습했다.
- **가상환경** — `venv` 생성·활성화·비활성화와 `pip`, `requirements.txt`로 프로젝트별 패키지 환경을 확인했다.
- **pathlib** — `Path`로 경로 정보 확인, 경로 결합, 디렉터리·파일 생성과 읽기/쓰기를 실습했다.
- **통합 실습** — `dataclass` + 패키지 + `pathlib`을 결합한 학습 기록 저장 프로그램을 완성하고, 실제 파일이 저장되는 것까지 확인했다.

## 막힌 부분
- **field와 attribute** — 클래스에 정의한 field와 객체에서 접근하는 attribute를 어떤 기준으로 구분해 말해야 하는지 헷갈렸다.
- **import 설명** — import할 때 모듈 코드가 실행되는 것, module namespace, `from ... import ...`가 서로 어떻게 이어지는지 말로 정확히 설명하지 못했다.
- **Path 메서드** — `Path.name`과 `suffix`가 무엇을 반환하는지 처음에 잘못 예상했다.
- **코드 설계** — `pathlib` 종합 문제와 마지막 통합 문제에서 개별 문법은 알았지만, 요구사항에 맞게 전체 코드를 스스로 연결하지 못했다.

## 시도한 것
- 예상 결과를 먼저 적어 두고 실제 출력과 비교했다.
- `which python`, `which pip`, `pip freeze`를 직접 실행해 가상환경과 패키지 위치를 확인했다.
- `Path()`만 쓴 경우와 `mkdir()`, `write_text()`까지 실행한 경우를 비교해, 경로 객체와 실제 파일 시스템 변경을 구분했다.
- 통합 문제는 막힌 부분을 단계별로 고치면서 패키지 구조, 객체 생성, 파일 저장까지 직접 실행해 확인했다.

## 배운 점
- **field와 attribute** — dataclass에서 선언한 `field`에 대응하는 값은 객체가 생성되면 각 객체의 attribute에 저장되고, `객체.attribute`로 접근한다.
- **`default_factory=list`** — 객체마다 별도의 리스트를 생성한다.
- **import의 동작** — import하면 모듈 코드가 실행되고, `__name__`으로 직접 실행인지 import인지 구분할 수 있다.
- **`__init__.py`** — 내부 이름을 여기서 가져오면, 패키지 이름만으로 필요한 객체와 함수를 바로 import할 수 있다.
- **가상환경** — 프로젝트별 Python·패키지 환경을 분리한다. `requirements.txt`에는 환경 자체가 아니라 필요한 패키지와 버전을 기록한다.
- **`Path`는 객체** — 문자열이 아니라 경로를 다루는 객체다. 실제 파일 시스템 변경은 `mkdir()`, `write_text()` 같은 작업을 해야 발생한다.

## 아직 모르는 점
- 여러 개념을 동시에 써야 하는 문제에서, 필요한 객체·함수·파일 구조를 처음부터 스스로 설계하는 능력이 부족하다.
- 패키지와 import의 내부 동작, `pathlib` 메서드 선택은 아직 반복 없이 바로 떠올릴 만큼 익숙하지 않다.
