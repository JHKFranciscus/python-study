## 막힌 부분

각각의 Flask/Jinja 문법보다, **요구사항을 보고 코드 전체의 연결 구조를 스스로 만드는 과정**에서 가장 많이 막혔다.

**1. 새 책 등록**

"새 책을 등록한다"는 요구사항에서, 입력값을 받는다 → 서버의 데이터에 추가한다 → 처리 후 목록으로 redirect한다는 흐름을 바로 떠올리지 못했다.

**2. 책 상세보기**

"책 제목을 클릭하면 해당 책의 상세정보를 보여준다"는 요구사항에서, 어떤 책을 선택했는지 서버가 알아야 하므로 id를 URL에 넣고 동적 route의 parameter와 연결해야 한다는 구조를 스스로 설계하지 못했다.

## 시도한 것

**시도 1. 직접 구현**

처음에는 직접 구현하려고 했지만 연결 구조를 만들지 못했다.

→ 결과: ChatGPT의 안내를 받으며 도서 목록, 등록, redirect, 상세보기 기능을 완성했다. 코드를 실행해서 정상 동작하는 것까지는 확인했다. 다만 구조를 만든 것은 내가 아니다.

**시도 2. 설계를 먼저 하는 방식으로 재시도**

코드를 바로 작성하지 않고, 화면 → 사용자 행동 → request → 서버가 하는 일 → response 순서로 먼저 설계한 뒤 구조를 다시 만들어 보려고 했다.

도저히 모르겠어서 ChatGPT가 하라는 대로 따라 했고, 가르쳐 주는 사고 순서대로 생각해 보려고 했는데도 구조를 만들지 못했다.

이 과정에서 **보기 → 읽기**, **특정 항목 보기 → 찾기**, **등록 → 추가**처럼 요구사항의 행동을 서버의 역할로 바꾸는 판단이 필요하다는 것을 확인했다.

→ 결과: ChatGPT를 통해 **나에게 설계 방식이 하나도 잡혀 있지 않다는 것**을 확인했고, 문법이 아니라 설계 방식부터 만들어야 한다는 결론을 얻었다. 여기서 시간이 다 되어 26일에는 중단했다.

## 배운 점

**`url_for()`**

- route 함수를 실행하는 것이 아니라, endpoint를 기준으로 URL을 만든다.
- 동적 route라면 URL을 완성하기 위해 필요한 값도 같이 전달해야 한다.

**`redirect()`**

- HTML을 직접 반환하는 것이 아니라, 브라우저가 새로운 request를 보내도록 하는 response다.
- `redirect()`가 실행되면 현재 request가 끝난 뒤 브라우저가 새로운 request를 보낸다.
- POST에서 사용한 `request.form`이 다음 GET으로 그대로 전달되는 것이 아니다. POST에서 서버의 데이터가 변경되고, 새로운 GET에서 그 변경된 데이터를 다시 읽는 것이다.

**Jinja의 들여쓰기**

- `{% if %}`, `{% for %}`는 Python처럼 들여쓰기가 실행 구조를 결정하지는 않는다.
- 다만 중첩 관계를 확인하기 위해 구조에 맞춰 들여쓰는 것이 좋다.

**HTTP response**

- status code는 처리 결과, header는 response 처리에 필요한 부가 정보, body는 실제 전달되는 내용을 의미한다.
- redirect response에서는 Location header가 브라우저가 새로 요청할 주소를 알려준다.

**지금 부족한 것은 설계 방식 자체다**

- ChatGPT를 통해 확인한 결과, 나에게는 설계 방식이 하나도 잡혀 있지 않았다.
- 요구사항의 행동을 서버의 역할로 바꾸는 판단이 필요하다는 것까지는 확인했다.
- 따라서 개별 문법을 더 보는 것보다 설계 방식을 먼저 만드는 것이 우선이다.

## 예상 꼬리 질문

**Q. 왜 redirect를 쓰나요?**
POST로 서버의 데이터를 변경한 뒤, 브라우저가 새로운 GET request를 보내게 해서 변경된 데이터를 다시 읽어 목록을 보여주기 위해서다. `request.form`의 값이 다음 GET으로 넘어가는 것이 아니다.

**Q. `url_for()`를 왜 쓰나요?**
endpoint를 기준으로 URL을 만들어 주기 때문이다. 동적 route라면 URL을 완성하는 데 필요한 값도 같이 전달해야 한다.

**Q. 결국 ChatGPT로 다 한 것 아닌가요?**
맞다. 그날은 기능 완성도, 원인 진단도 ChatGPT를 거쳐 나왔다. 그래서 이걸 구현 경험이 아니라 "아직 못 하는 것을 확인한 기록"으로 남겼다. 코드가 돌아간 것과 내가 만들 수 있는 것은 다르다고 보고, "안내 구현 완료"와 "독립 재구성 완료"를 따로 적고 있다.

**Q. 그럼 ChatGPT 없이 할 수 있는 건 뭔가요?**
개별 문법은 배운 상태다. 못 하는 건 요구사항에서 전체 구조를 만들어내는 부분이다. 그래서 다음 날 시간을 빼서 안내 없이 다시 구현하는 방식으로 확인하고 있다.

## Status code 정리 (학습한 내용)

- **200** — 요청이 정상적으로 처리됨
- **302** — redirect. Location header에 적힌 주소로 브라우저가 다시 요청함
- **404** — 요청한 주소를 찾을 수 없음
- **405** — 주소는 존재하지만 해당 HTTP method는 허용되지 않음
