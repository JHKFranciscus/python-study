## 막힌 점 → 시도한 것

**1. mongod 연결이 거부됨 (localhost:27017)**
- 막힌 점: Flask와 mongod가 서로 다른 WSL 환경에서 실행되고 있었다.
- 시도: Flask가 실행되는 환경과 MongoDB가 실행되는 환경을 각각 확인해서 해결했다.

**2. 의도하지 않은 URL로 요청이 감**
- 막힌 점: form의 action에 따옴표와 `>`가 누락돼 있었다.
- 시도: VS Code 터미널의 Flask 요청 로그에 `GET /tasks%20method=...` 404처럼 의도하지 않은 path가 찍힌 걸 보고, form의 action에 있던 따옴표와 `>` 누락을 수정했다.

**3. Update/Delete에 쓸 _id 연결**
- 막힌 점: 독립 구현에서 실제 _id를 HTML에 어떻게 연결할지 막혔다.
- 시도: 동적으로 _id를 출력하는 방법은 아직 안 배웠으니, 조회한 _id를 form URL에 직접 넣어서 Update/Delete 동작을 확인했다.

**4. `ObjectId is not JSON serializable` 오류**
- 막힌 점: `list(tasks.find())`를 그대로 반환했더니 오류가 났다.
- 시도: `str(list(...))`로 바꿔서 지금 학습 범위 안에서 응답을 확인했다.

---

## 배운 점

**연결 구조**
- mongosh와 PyMongo는 각각 독립적으로 mongod에 접근한다.

**PyMongo 반환값**
- `find()`는 Cursor를 반환한다. `list(find())`를 해야 document들이 들어 있는 list가 된다.
- `insert_one()`, `update_one()`, `delete_one()`의 반환값은 실제 document가 아니라 각각 InsertOneResult, UpdateResult, DeleteResult 같은 결과 객체다.

**Flask와 form**
- form의 name이 request 데이터의 key가 되고, `request.form.get()`으로 사용자가 입력한 값을 받을 수 있다.

**ObjectId와 JSON**
- URL에서 받은 _id는 문자열이라, MongoDB의 ObjectId와 비교하려면 변환이 필요하다.
- BSON에는 ObjectId가 있지만 일반 JSON에는 없기 때문에 그대로 JSON 직렬화할 수 없다.
- `str()` 변환은 JSON 직렬화가 아니다.

## 아직 부족한 부분

- Flask + MongoDB CRUD는 최종 동작까지 성공했지만 완전한 독립 구현은 아니었다.
- 특히 ObjectId 변환, POST method 설정, 조회 결과 반환 부분에서 교정이 필요했다.
- 조회한 document의 _id를 HTML의 Update/Delete 버튼에 자동으로 연결하는 방법은 아직 안 배웠다.
