## 1. MongoDB shell — Update / Delete

**한 일**
`updateOne()`, `updateMany()`, `$set`, `deleteOne()`, `deleteMany()` 실습

**막힌 점 1**
Ubuntu 24.04의 `mongod`와 Ubuntu 26.04의 `mongosh`가 분리된 환경이라, MongoDB 서버를 다시 실행하는 데 시간이 많이 걸렸다.
→ Ubuntu 24.04에서 mongod를 실행하고 해당 WSL을 유지한 상태에서 Ubuntu 26.04의 mongosh와 PyMongo로 접속해 해결했다. 다만 왜 현재 환경이 이런 방식으로 동작하는지는 아직 독립적으로 설명하지 못한다.

**막힌 점 2**
`ObjectId()` 안의 문자열, 쉼표·따옴표, field 이름을 자주 틀렸다. `completed`를 `comleted`로 입력해서, 기존 field가 수정된 게 아니라 새 field가 생겼다.

**시도 2**
- 작업 전후로 `find()` / `findOne()`을 돌려서 실제 document를 직접 확인했다.
- 오타로 생긴 `comleted` field는 제거하고 `completed`를 정상 값으로 다시 수정했다.

**배운 점 2**
- Update는 **수정할 document를 찾는 조건**과 **어떻게 수정할지에 대한 명령**을 나눠서 쓴다.
- `$set`에 존재하지 않는 field 이름을 쓰면 오류가 아니라 새 field가 만들어진다. 그래서 field 이름 오타는 조용히 넘어간다. 이름을 정확히 확인해야 한다.

## 2. PyMongo — CRUD 연결

**한 일**
- `update_one()`, `update_many()`, `delete_one()`, `delete_many()` 실습
- `matched_count`, `modified_count`, `deleted_count`로 작업 결과 확인
- `inserted_id`로 document 하나를 계속 추적하며 Create → Read → Update → Delete 연결
- 여러 document를 생성하고 조건에 따라 수정·삭제하는 CRUD 재현

**막힌 점 1**
`inserted_id`, `inserted_ids`, `matched_count`, `modified_count`, `deleted_count` 같은 Result 객체의 속성을 정확히 기억하지 못했다.

**막힌 점 2**
CRUD 재현에서 `inserted_ids`, `update_one()` 사용, 수정 후 재조회, 마지막 남은 데이터 확인에 교정이 필요했다.

**시도 1·2**
- 생성 시 받은 `_id`를 저장해두고, Read → Update → Delete에서 같은 `_id`를 계속 사용했다.
- Update 결과와 실제 document는 다르므로, 수정 후 `find_one()`으로 다시 조회해서 값을 확인했다.

**배운 점 1·2**
- `matched_count`는 조건에 맞은 개수, `modified_count`는 실제로 값이 바뀐 개수다. 그래서 둘이 다를 수 있다.
- `insert_one()`으로 받은 `_id`는 `{"_id": task_id}`처럼 그대로 조건에 넣어 쓸 수 있다.
- `update_one()`의 반환값은 수정된 document 자체가 아니라 **수정 작업의 결과**다. 실제 document를 확인하려면 다시 조회해야 한다.

## 3. 알고리즘 — dictionary 누적

**한 일**
과목별 점수의 합계와 횟수를 dictionary에 누적하고, 평균이 가장 높은 과목 찾기

**막힌 점**
- 처음 등장한 key의 내부 dictionary가 아직 없는데 내부 값에 먼저 접근해서 `KeyError`가 났다.
- dictionary를 순회할 때 반복 변수에 key가 들어온다는 점도 혼동했다.

**시도**
처음 등장한 key일 때는 내부 dictionary를 통째로 먼저 만들고, 그 다음 등장부터 `total`과 `count`를 누적하도록 수정했다.

**배운 점**
dictionary 하나의 key에 합계와 횟수처럼 값을 여러 개 저장하려면, dictionary 안에 dictionary를 둘 수 있다.

## 4. CS — 프로그램 / 프로세스 / 스레드

**한 일**
프로그램, 프로세스, 스레드 구분과 프로세스별 메모리·공통 외부 저장소의 차이 확인

**배운 점**
같은 프로세스의 스레드는 메모리를 공유할 수 있지만, 서로 다른 프로세스는 각자 메모리를 가진다. 그래도 서로 다른 프로세스가 같은 MongoDB를 사용하면 같은 저장 데이터를 볼 수 있다.
