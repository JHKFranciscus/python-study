## 막힌 점
- `__str__`, `__len__`, `__iter__` 각각의 역할을 정확히 구분하지 못했다.
- `__iter__()`가 반환해야 하는 대상과, 반복 과정에서 실제로 나오는 값을 혼동했다.
- 독립 재현에서 주어진 예제에 맞추려고 짝수만 통과시키는 조건을 넣어, 일반적인 반복 규칙을 잘못 만들었다.
- `__len__()`에서 값을 모두 `list`로 만든 뒤 길이를 구해 문제의 조건을 만족하지 못했다.
- `dataclass`의 field와 객체의 attribute가 어떤 관계인지, 두 용어를 어떤 상황에서 사용하는지 바로 구분하지 못했다.

## 시도한 것
- `for`문과 `iter()` / `__iter__()`의 호출 관계를 다시 확인했다. → 역할 구분과 반환값 혼동을 정리했다.
- 독립 재현의 `__iter__()`에서 불필요한 짝수 조건과 `list()` 생성을 제거했다. → 예제에만 맞춘 규칙을 걷어냈다.
- `start`, `final`, `step`만 이용해 길이를 계산하도록 수정했고, 이후 `len(range(...))`을 사용하는 정석적인 방식도 확인했다. → `__len__()`의 조건을 만족시켰다.
- 같은 `Box` 객체를 여러 변수가 참조하는 경우와, 서로 다른 `Box` 객체가 같은 `list`를 참조하는 경우를 직접 비교했다.
- `dataclass`와 일반 클래스를 비교하여 자동 생성되는 메서드의 차이를 확인했다. → field와 attribute의 쓰임을 구분해 보았다.

## 배운 것
- `__str__`은 객체를 어떤 문자열로 보여줄지, `__len__`은 `len(객체)`가 돌려줄 값을, `__iter__`는 `iter(객체)`가 돌려줄 iterator를 정의한다.
- `__repr__`은 개발·디버깅 과정에서 객체의 내용을 더 명확하게 확인하려고 쓰는 표현이다. `list` 안에 들어 있는 객체를 출력할 때 `list`는 각 원소의 `repr` 표현을 사용한다.
- `__eq__`를 정의하면 서로 다른 객체라도 내가 정한 기준으로 `==` 비교가 가능하다.
- 객체 자체가 서로 달라도 내부 속성은 같은 객체를 참조할 수 있다.
- `range`는 `list`로 변환하지 않아도 이미 iterable이며, `iter(range(...))`로 iterator를 얻을 수 있다.
- 길이는 원소를 전부 만들지 않아도 `start`, `final`, `step`만으로 계산할 수 있다.
- 예제에 맞춘 조건을 넣으면 그 예제만 통과할 뿐, 일반적인 규칙은 깨진다.
- `@dataclass`는 dataclass가 관리할 데이터 항목인 field를 바탕으로 `__init__`, `__repr__`, `__eq__` 등을 자동 생성하며, field에는 기본값도 지정할 수 있다.

## 아직 모르는 것
- 실제 프로그램에서 특수 메서드를 언제 직접 정의하는 것이 적절한지는 더 경험이 필요하다.
- `__repr__`은 아직 맛보기 수준이다. `__str__`과 언제 나눠 써야 하는지, f-string의 `!r`이 정확히 어떤 동작인지는 더 확인이 필요하다.
- `field`와 `attribute`라는 용어를 상황에 맞게 자연스럽게 구분하는 것은 아직 익숙하지 않다.
- 새로운 요구사항만 보고 `__iter__()`의 반복 구조를 처음부터 설계하는 것은 아직 안정적이지 않다.
