# Flask 공부일지 — HTML template과 form 입력값 처리

**한 줄 요약**
HTML form의 `action`, `method`, input `name`이 브라우저가 보낼 HTTP request를 정하고, Flask는 그 request를 route와 함수로 연결한다. GET은 query string(`request.args`), POST는 request body의 form 데이터(`request.form`)로 값이 들어온다.

**외워둘 흐름 3줄**

- `form action` → request path → Flask route → 함수
- `input name` → GET query string / POST body → `request.args` / `request.form`
- Python 변수 → `render_template()` → Jinja `{{ }}` → 결과 HTML

---

## 1. 오늘 한 일

- `templates` 폴더와 `render_template()`으로 HTML을 응답으로 만드는 과정을 확인했다.
- Jinja의 `{{ }}`로 Python 값을 template에 전달해서 화면에 출력했다.
- HTML form의 `action`, `method`, input의 `name`이 HTTP request와 어떻게 연결되는지 확인했다.
- GET form과 POST form을 각각 실행해서 입력값이 실리는 위치의 차이를 확인했다.
- 같은 `/profile` path에 GET과 POST를 모두 허용하고 `request.method`로 입력 화면 표시와 form 처리를 나눴다.
- 마지막에는 검색은 GET, 문의 등록은 POST를 쓰는 프로그램을 처음부터 구성했다.

## 2. 막힌 점

**(1) HTML form과 Flask route가 어떻게 연결되는지 몰랐다**
`action="/search"`가 Python 함수를 바로 실행하는 줄 알았다. 브라우저가 request를 새로 만들어 보낸다는 단계가 빠져 있었다.

**(2) URL이 바뀌면 서버도 바뀌는 건지 혼동했다**
주소창이 `/`에서 `/search?...`로 바뀌는 걸 보고 다른 서버로 넘어간 건가 싶었다.

**(3) GET과 POST에서 path, HTTP method, 데이터 위치가 서로 섞였다**
무엇이 path이고 무엇이 method인지, 값이 어디에 실리는지가 정리되지 않았다.

**(4) 마지막 독립 재현에서 Flask endpoint 충돌 오류가 났다**
서로 다른 route에 같은 함수 이름을 써서 실행이 되지 않았다.

## 3. 시도한 것 (막힌 점과 같은 번호)

**(1)** form을 직접 제출해 보면서, `action="/search"`는 브라우저가 `/search`로 새 HTTP request를 보내는 것이고 그 request가 Flask routing을 거쳐 함수와 연결된다는 순서를 확인했다.

**(2)** 주소가 바뀔 때마다 host와 port를 확인했다. `127.0.0.1:5000`이 그대로면 같은 Flask 서버이고 path와 query string만 달라진 것이라고 정리했다.

**(3)** GET form을 실행해 주소창에 `?nickname=minsu`가 붙는 것을 확인하고 `request.args.get()`으로 값을 꺼냈다. 같은 예제를 POST로 바꾼 뒤에는 주소창에 입력값이 보이지 않아도 `request.form.get()`으로 값이 오는 것을 확인했다. 그다음 `/profile` 하나에 GET과 POST를 모두 허용하고 `request.method`에 따라 다르게 처리하는 코드를 구현했다.

**(4)** 최초 실행에서는 함수 이름 중복으로 실패했고, 오류 원인을 확인한 뒤 route 함수 이름을 서로 다르게 분리해서 정상 실행했다. 원인은 스스로 찾은 것이 아니라 안내를 받고 알았다.

## 4. 배운 것 (막힌 점과 같은 번호)

**(1)** HTML form은 브라우저에게 새 HTTP request를 어떻게 만들지 알려주는 역할이다. `action`은 request를 보낼 path를 정하고, `method`는 GET과 POST 중 어떤 HTTP method를 쓸지 정하고, input의 `name`은 서버로 전송될 데이터의 이름이 된다.

**(2)** URL과 서버는 같은 개념이 아니다. 같은 Flask 서버 하나에서도 `/`, `/search`, `/profile`처럼 여러 path를 쓸 수 있다.

**(3)** GET form은 입력 데이터가 URL의 query string으로 전달되고 Flask에서는 `request.args`로 접근한다. POST form은 입력 데이터가 HTTP request body의 form 데이터로 전달되고 `request.form`으로 접근한다. POST는 입력값이 주소창에 보이지 않을 뿐이고 데이터를 암호화하는 방식은 아니다.

**(4)** Flask에서 route 함수 이름은 endpoint 이름으로 쓰이기 때문에, 서로 다른 route라도 함수 이름이 겹치면 충돌 오류가 난다.

**(추가로 확인한 것) `render_template()`은 원본 HTML 파일을 수정하지 않는다.**
Jinja가 template을 읽어서 렌더링된 HTML 문자열을 메모리에서 만들고, 그 결과를 응답으로 보낸다.

## 5. 아직 부족한 부분

- 개념을 하나씩 보면 이해가 되는데, route와 template이 여러 개 한꺼번에 나오면 다음 연결을 빠르게 판단하는 것이 아직 느리다.
- endpoint 함수 이름 중복 오류는 원인을 안내받은 뒤에 해결했다. route를 여러 개 만들 때 함수 이름까지 스스로 점검하는 습관이 아직 안 잡혔다.

## 6. 내일 할 것

- 오늘 배운 Flask 요청 데이터 흐름을 짧게 다시 확인한 뒤 다음 Flask 진도를 진행한다.
- 코드를 쓸 때 순서를 정해서 확인한다. 먼저 path와 method를 정하고 → form의 `action`이 Flask route와 연결되는지 확인하고 → input의 `name`과 `request.args` 또는 `request.form`에서 찾는 이름이 같은지 확인한다.

# 부록 (면접 전에 다시 보는 용)

## A. 한 문장 요약

Flask에서 HTML form 입력값을 받을 때 GET과 POST의 데이터 전달 경로가 다르다는 것을 직접 실행해 보면서 정리한 경험이다.

## B. 30초 답변 구조

1. **상황** — Flask에서 template과 form을 처음 다뤘는데, form의 `action`이 Python 함수를 바로 부르는 줄 알았다.
2. **문제** — 그래서 어느 route로 가는지, 값이 어디에 실리는지가 계속 헷갈렸다.
3. **행동** — GET form과 POST form을 각각 실행해서 주소창과 받는 코드(`request.args` / `request.form`)를 직접 비교했다. 그다음 `/profile` 하나에 GET과 POST를 모두 붙여 `request.method`로 나누는 것까지 해봤다.
4. **결과** — form → 브라우저가 새 request 생성 → Flask route → 함수 순서로 흐름을 정리했고, 마지막에 검색은 GET, 문의 등록은 POST를 쓰는 프로그램을 직접 구성했다.

## C. 예상 꼬리 질문과 답변 방향

**Q. GET과 POST는 언제 어떤 걸 쓰나?**
직접 해본 범위에서는 검색처럼 조회하는 것은 GET, 문의 등록처럼 값을 보내는 것은 POST로 만들었다. GET은 값이 URL query string에 남고 POST는 body로 간다는 차이를 기준으로 설명한다.

**Q. POST를 쓰면 데이터가 안전한가?**
주소창에 보이지 않을 뿐이고 암호화되는 것은 아니라고 답한다.

**Q. `request.args`와 `request.form`의 차이는?**
`request.args`는 URL query string에서, `request.form`은 request body의 form 데이터에서 값을 꺼낸다고 답한다.

**Q. `render_template()`을 쓰면 HTML 파일이 바뀌나?**
원본 파일은 그대로이고, Jinja가 렌더링한 HTML 문자열을 만들어서 응답으로 보낸다고 답한다.

**Q. endpoint 충돌 오류는 어떻게 해결했나?**
원인 자체는 안내를 받고 알았다고 솔직히 말한다. 다만 오류가 난 상황을 만들어 확인하고, 함수 이름을 분리한 뒤 다시 실행해서 정상 동작을 확인한 것은 직접 했다고 덧붙인다. 그 뒤로는 route를 추가할 때 함수 이름부터 본다고 말한다.
