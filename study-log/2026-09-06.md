## 설명할 수 있게 된 핵심 흐름

**조회(GET)**
fetch() → GET request → Flask route → MongoDB 조회 → JSON response → response.json() → DOM 생성

**저장(POST)**
JavaScript object → JSON.stringify() → request body → request.get_json() → Python dictionary → MongoDB

**_id 이동**
MongoDB ObjectId → string → JavaScript / URL → Flask string → ObjectId → MongoDB

**CRUD 후 다시 GET하는 이유**
화면이 JavaScript가 예상한 상태가 아니라, 현재 DB에 실제로 저장된 상태를 기준으로 만들어지기 때문이다.

## 오늘 빠뜨린 것 → 내일 코드 쓸 때 확인할 것
- [ ] DOM element 자체를 보내지 않고 `.value`를 붙였는가
- [ ] POST body에 `JSON.stringify()`를 했는가
- [ ] MongoDB 수정에 `$set`을 넣었는가
- [ ] 페이지 최초 진입 시 조회 함수를 호출했는가
- [ ] JavaScript 변수 선언과 DOM 조회 코드가 맞는가

개념 교정: non-empty string은 truthy이므로 `!"false"`는 `false`다. "false"라는 string에 `!`을 붙여도 boolean true가 되지 않는다.
