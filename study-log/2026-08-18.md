# 7주차 2일차 공부일지

**한 줄 요약**
배열·반복문·함수·return·DOM event 연결을 학습했고, 마지막 독립 재현에서 여러 DOM 요소를 가져오는 판단에 실패해 안내 후 보완했다.

---

## 오늘 한 일

**배열과 반복문**
배열의 index와 `.length`를 이용해 요소 하나에 접근하고, `for`로 배열 전체를 순회했다. 순회하면서 조건을 만족하는 요소의 개수를 세거나, 현재까지의 최댓값을 갱신하는 코드를 작성했다.

**함수**
선언과 호출, parameter와 argument, return을 다뤘다. 호출부에서 전달한 값이 parameter에 들어가는 과정을 추적하고, 함수가 계산한 값을 return해 다른 코드에서 사용하는 흐름을 연습했다.

**DOM**
`querySelectorAll()`로 같은 class를 가진 여러 요소를 NodeList로 가져오고, 반복문으로 각 요소에 접근했다. 이어서 여러 버튼 각각에 click event를 등록하고, event가 발생한 뒤 함수가 실행되어 `textContent`를 변경하도록 구현했다.

**CS**
Call Stack으로 함수 호출과 복귀 과정을 확인했다. 또한 `addEventListener("click", 함수)`는 함수를 즉시 실행하는 것이 아니라, 나중에 event가 발생했을 때 실행할 함수 자체를 등록한다는 점을 다시 확인했다.

---

## 막힌 부분 (증상 → 원인)

**1. selector 혼동 (`#` vs `.`)**
여러 DOM 요소 변경 실습에서 요소를 찾지 못했다. HTML에는 `class="status"`가 있었는데 `querySelectorAll("#status")`로 작성한 것이 원인이었다. `#`는 id, `.`은 class selector다.

**2. 속성 이름 오타 (`contentText`)**
여러 버튼 event 실습에서 event는 실행되는데 화면 문구가 바뀌지 않았다. `textContent`를 `contentText`로 잘못 작성한 것이 원인이었다.

**3. `let` 누락**
count, i, 최댓값 변수 등을 만들면서 `let`을 빠뜨리는 실수가 여러 번 반복됐다.

**4. 단수/복수 판단 실패 (`querySelector`)**
마지막 독립 재현에서 `result[0]`에 접근하다 오류가 발생했다. 결과 `<p>` 두 개를 같은 class로 만들어 놓고, `querySelector()`를 사용해 첫 번째 요소 하나만 가져온 것이 원인이었다.

---

## 시도한 방법 (해결 → 확인)

**1.** HTML의 class와 JavaScript selector를 직접 비교해 `.status`로 수정했고, 네 개의 문구가 모두 변경되는 것을 확인했다.

**2.** `contentText`를 `textContent`로 수정한 뒤, 세 버튼 모두에서 DOM 변경이 정상적으로 이루어지는 것을 확인했다.

**3.** 빠뜨린 `let` 선언을 추가했다.

**4.** `querySelector()`를 `querySelectorAll()`로 수정했다. 이후 일반 함수 `printResult`를 만들어 `addEventListener("click", printResult)`로 연결했다.

독립 재현에서는 처음부터 70점 이상 개수를 계산하는 함수와 최댓값을 계산하는 함수를 만들고 각각 결과를 return하도록 작성했다. 버튼의 click event 이후 결과 DOM을 변경하는 구조까지는 직접 구성했다.

보완 과정에서는 scores와 result가 함수 바깥 scope에 존재하므로, parameter로 전달하지 않아도 함수 내부에서 접근할 수 있다는 점도 확인했다. 최종적으로 버튼 클릭 전에는 `-`, `-`가 표시되고 클릭 후에는 `3`, `91`이 표시되는 것을 확인했다.

## 배운 점

- **배열 전체와 요소 하나를 구분해야 한다.** scores는 배열 전체이고, `scores[i]`는 현재 index의 요소 하나다.
- **함수 자체가 필요한지, 반환값이 필요한지를 구분해야 한다.** `addEventListener()`에는 함수 자체를 등록하지만, 계산 결과가 필요한 곳에서는 `count70()`처럼 함수를 호출해야 한다.
- **DOM은 찾기 전에 대상이 하나인지 여러 개인지를 먼저 판단해야 한다.** `querySelector()`는 일치하는 첫 요소 하나를 가져오고, `querySelectorAll()`은 여러 요소를 NodeList로 가져온다.
- **함수 내부에서 변수를 찾지 못하면 바깥 scope에서 찾을 수 있다.** 그래서 이번 코드에서는 `count70()`과 `maximumScore()`가 바깥의 scores를 직접 사용할 수 있었다.

## 아직 부족한 부분

오늘 막힌 부분은 모르는 문법이 아니라, **설명할 수 있는 문법을 작성 중에 적용하지 못한 경우**였다.

- `let`과 `const`의 차이는 알고 있지만, 실제 작성 중 새 변수를 선언할 때 `let`을 빠뜨리는 일이 반복됐다.
- `querySelector()`와 `querySelectorAll()`의 차이는 설명할 수 있음에도, 독립 재현에서는 필요한 DOM 요소가 하나인지 여러 개인지를 먼저 판단하지 못했다.
- `#`와 `.`, `textContent`처럼 이미 배운 문법도 실제 작성 과정에서는 이름을 잘못 쓰는 경우가 있었다.

오늘 독립 재현에서는 배열 계산, 함수, return, event 연결이라는 큰 구조는 직접 구성했지만, 여러 DOM 요소를 가져오는 판단에서 실패했다. 따라서 결과는 **최초 독립 재현 실패 → 안내 후 보완 성공**이다.
