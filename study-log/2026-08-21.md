DOM 요소 vs jQuery 객체 / method 자체 vs method 호출 / library 로드 순서 / 독립 재현 검증

> 한 줄 요약: jQuery로 DOM을 다루는 방법을 익혔고, 버튼을 눌러도 화면이 바뀌지 않던 원인이 jQuery library 미연결이라는 것을 찾아 해결했다.

## 오늘 한 일

- jQuery의 `$()`로 요소를 선택하고 `.text()`, `.val()`, `.attr()`, `.css()`와 class 관련 method를 학습했다.
- `.on()`으로 click event와 handler를 연결하고, `event.target`으로 실제 event가 발생한 DOM 요소를 다루는 방법을 확인했다.
- 일반 JavaScript의 DOM 요소와 jQuery 객체를 비교하며 각각 사용할 수 있는 property와 method를 구분했다.
- 독립 재현으로 도서 제목과 가격을 입력받아 계산 결과를 표시하고, 가격에 따라 `cheap` class를 추가·제거하는 미리보기 기능을 구현했다. (기능 요구사항 7개)
- CS에서는 event, event handler, callback, event-driven programming의 관계를 학습했다.
- SSAFY 개인 문제집을 자체 진행했다.

## 막힌 점

- **method 표기**: `.val`과 `.val()`을 혼동해 method 자체와 method 실행 결과를 정확히 구분하지 못했다.
- **selector 표기**: selector를 작성할 때 id를 나타내는 `#`을 빠뜨렸다.
- **변수 선언**: 독립 재현에서 새 변수 `numPrice`를 선언하면서 `const`를 빠뜨렸다.
- **실행 환경**: 독립 재현 코드를 다 작성하고 실행했는데, 버튼을 눌러도 화면이 바뀌지 않았다.

## 시도한 것

- `.val`과 `.val()`을 비교하여 전자는 method 자체이고, 후자는 method를 실행해 value를 반환받는 것임을 다시 확인했다.
- `numPrice`를 각 함수 내부에서 `const`로 선언하도록 수정했다.
- 버튼이 동작하지 않는 원인을 확인한 결과, jQuery library가 HTML에 연결되어 있지 않은 것을 찾았다.
- jQuery library를 내 JavaScript 파일보다 먼저 불러오도록 수정한 뒤 다시 실행했다.
- 가격을 `5000`과 `20001`로 각각 입력하여, 계산 결과뿐 아니라 `cheap` class의 추가·제거까지 실제 화면에서 확인했다.

## 배운 점

- 코드를 읽을 때 먼저 지금 다루는 값이 DOM 요소인지 jQuery 객체인지 판단해야, 사용할 property와 method를 결정할 수 있다.
- `event.target`은 DOM 요소이고, `$(event.target)`은 그 DOM 요소를 jQuery 방식으로 다루기 위한 jQuery 객체이다.
- input의 `.val()`은 문자열을 반환하므로, 숫자 계산이 필요하면 `Number()` 등으로 자료형을 변환해야 한다.
- selector를 전달하는 자리와 class 이름 자체를 전달하는 자리는 다르다. `$("#card")`에서는 `#`이 필요하지만 `.addClass("active")`에서는 `.`을 붙이지 않는다.
- event handler는 event를 처리한다는 역할에 따른 이름이고, callback은 함수 자체가 다른 코드에 전달되어 나중에 호출되는 방식에 따른 이름이다.
- 코드 내용이 맞는 것만으로는 충분하지 않다. 외부 library가 필요한 경우, 그 library가 먼저 load되어 실제 실행 환경이 준비되어 있는지도 확인해야 한다.

## 아직 부족한 부분

- 새 변수를 만들 때 `const`나 `let` 선언을 빠뜨리는 실수를 코드 작성 단계에서 바로 잡지 못했다.
- method 자체와 method 호출, selector 문자열과 단순 이름처럼 모양이 비슷한 표현을 작성 중에 더 빠르게 구분할 필요가 있다.
- 코드 자체뿐 아니라 `<script>` 연결과 실행 순서까지 포함해서, 프로그램이 실제로 동작하기 위한 조건을 확인하는 습관이 더 필요하다.
