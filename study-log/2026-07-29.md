# 2026년 7월 29일 공부일지

**한 줄 요약**: 상속과 `super()`, 오버라이딩을 학습했다. 관리 클래스가 공통 기능만 사용하면 자식 클래스를 추가해도 관리 코드를 바꾸지 않아도 된다는 것을 확인했다.

## 오늘 한 일
- 인스턴스 속성, 클래스 속성, 인스턴스 메서드, 클래스 메서드, 정적 메서드를 복습했다.
- 부모 클래스와 자식 클래스의 상속 관계를 학습했다.
- 자식 클래스에서 부모의 생성자와 메서드를 호출하는 `super()`를 학습했다.
- `EBook`과 `AudioBook`에서 `show_info()`를 오버라이딩했다.
- `BookManager`에 일반 도서, 전자책, 오디오북 객체를 함께 저장하고 조회·검색·가격 변경·삭제 기능을 구현했다.
- 상속의 is-a 관계와 객체 구성의 has-a 관계를 비교했다.
- `Product`, `DownloadProduct`, `ProductManager` 구조를 코드를 보지 않고 다시 구현했다.

## 막힌 점
- `EBook` 객체가 `Book`의 인스턴스이기도 하다는 것을 처음에는 몰랐다.
- `show_all_books()`에서 결과 리스트를 반복문 안에서 만들었다. 반복할 때마다 리스트가 새로 만들어져서 마지막 객체만 남았다.
- `change_book_price()`에서 같은 가격 변경 메서드를 두 번 호출했다. 한 번이면 되는 작업이 두 번 실행되는 구조였다.
- 독립 재현에서 검색 실패값은 `None`인데 조건문에서 `False`와 비교했다. 없는 상품의 가격을 변경하면 오류가 날 수 있는 구조였다.
- 상속 관계와 객체 구성 관계는 코드의 동작은 알았지만, 그 이유를 문장으로 설명하는 데 막혔다.

## 시도한 것
- `isinstance()`로 예상 결과와 실제 결과를 비교해서 자식 객체와 부모 클래스의 관계를 확인했다.
- 결과 리스트를 만드는 위치를 반복문 밖으로 옮겨서 모든 정보가 쌓이도록 수정했다.
- 찾은 객체의 `change_price()`를 한 번만 호출하고, 그 반환값을 그대로 반환하도록 수정했다.
- 검색 실패값에 맞춰 조건을 `is not None`으로 바꿨다.
- `AudioBook`을 추가한 뒤 기존 `BookManager`를 수정하지 않고 등록·검색·가격 변경이 되는지 확인했다.

## 배운 점
- 상속은 자식 클래스가 부모 클래스의 한 종류일 때 사용한다. 이것이 is-a 관계다.
- 객체 구성은 한 객체가 다른 객체를 가지고 사용하는 관계다. 이것이 has-a 관계다.
- 자식 클래스에 메서드가 없으면 부모 클래스에서 찾아 사용한다.
- 자식 클래스에 부모와 같은 이름의 메서드를 쓰면 자식 메서드가 먼저 선택된다. 이것이 오버라이딩이다.
- `super()`를 사용하면 부모의 공통 초기화와 기능을 중복 없이 재사용할 수 있다.
- 부모 생성자와 자식 생성자는 서로 다른 객체를 만들지 않는다. 둘 다 같은 자식 인스턴스를 대상으로 실행된다.
- 관리 클래스가 공통 속성과 공통 메서드만 사용하면, 자식 클래스를 새로 추가해도 관리 코드를 바꾸지 않아도 된다.
- `None`은 객체 검색 실패, `False`는 작업 실패를 뜻하도록 역할을 나눠야 한다.

## 아직 모르는 것
- 새로운 사례에서 상속과 객체 구성 중 무엇을 고를지 바로 판단하는 연습이 더 필요하다.
- 여러 단계로 이어지는 상속과 여러 부모 클래스를 상속하는 구조는 아직 학습하지 않았다.
