# 공부 일지 — iterator와 generator

## 한 줄 요약

iterator는 진행 위치를 기억하면서 값을 하나씩 제공하는 객체이고, generator는 iterator의 한 종류로서 `yield`가 있는 함수나 generator 표현식으로 만들며 필요한 값을 요청받을 때 하나씩 생성한다.

## 오늘 한 일

**iterator**

- iterable과 iterator의 차이를 학습하고 `iter()`, `next()`, `StopIteration`의 동작을 직접 확인했다.
- 같은 iterable에서 만든 iterator들은 진행 위치를 서로 공유하지 않는다는 것을 실험했다.
- `for`문이 값을 하나씩 요청하다가 `StopIteration`을 만나면 반복을 끝내는 과정을 `while`, `try`, `except`로 재현했다.

**generator**

- `yield`가 있는 generator 함수와 generator 표현식으로 generator 객체를 만드는 방법을 학습했다.
- `next()`를 호출할 때 generator가 이전 `yield`에서 실행을 재개해 다음 `yield`까지 진행하는 과정을 확인했다.
- 온도 기록과 서버 응답 시간 데이터에서 조건을 만족하는 기록만 generator로 순차 생성했다.

**지연 계산과 메모리**

- 리스트 컴프리헨션의 즉시 계산과 generator 표현식의 지연 계산을 비교했다.
- `sys.getsizeof()`로 결과 100,000개를 저장한 리스트와 generator 객체의 크기를 비교했다.

**그 외**

- SSAFY 문제 풀이는 별도로 완료했다.

## 막힌 부분

- **예상과 실제가 달랐던 것 1** — `iter()`로 iterator를 만들면 원본 요소도 복사될 것이라고 예상했다. 하지만 iterator는 원본 리스트 안의 딕셔너리를 그대로 전달했고, 처음에는 이 차이를 구분하지 못했다.
- **예상과 실제가 달랐던 것 2** — generator 표현식을 생성할 때 내부 계산이 한 번은 실행될 것으로 예상했지만, 실제 실행 횟수는 0번이었다.
- **말로 정리가 안 됐던 것** — generator가 `yield`에서 멈추는 것과 다음 `next()`에서 실행을 재개하는 과정을 정확한 말로 정리하는 데 혼동이 있었다.
- **서버 점검 독립 재현에서 낸 실수 2가지**
  - `for check in checks`로 이미 꺼낸 딕셔너리인 `check`에 다시 `next()`를 사용했다.
  - 현재 서버의 응답 시간을 기준값과 비교해야 했지만, 처음에는 기준값 자체를 `300`과 비교했다.

## 시도한 것

- 같은 iterable로 iterator 두 개를 만든 뒤 `next()` 호출 순서를 다르게 해서 진행 위치가 독립적인지 확인했다.
- 소진된 iterator를 직접 `next()`로 호출했을 때와 `for`문으로 순회했을 때의 차이를 비교했다.
- generator 함수 안에 출력문을 배치해서 각 `next()`가 어느 코드까지 실행시키는지 확인했다.
- 첫 번째 조건 만족 값은 `next()`로 받고, 남은 값은 같은 generator를 `for`문으로 이어서 처리했다.
- 독립 재현 코드에서 반복 변수 `check`에 실제로 들어 있는 값과 조건식의 좌우 항을 다시 확인한 뒤 코드를 수정했다.
- 리스트와 generator에 동일한 제곱 계산을 적용해 계산 시점과 객체 크기를 비교했다.

## 배운 점

- iterable은 반복할 수 있고 iterator를 만들 수 있는 객체이고, iterator는 현재 진행 상태를 기억하면서 다음 값을 제공하는 객체다.
- 이번에 사용한 리스트 iterator는 원본 리스트의 요소를 복사하지 않고 그대로 전달하므로, 꺼낸 가변 객체를 수정하면 원본도 변경될 수 있다.
- iterator는 모두 소진돼도 처음으로 자동 복귀하지 않고, 다시 값을 요청하면 `StopIteration`이 발생한다.
- `for`문은 내부적으로 값을 계속 요청하다가 `StopIteration`을 만나면 반복을 정상 종료한다.
- generator는 `yield`가 있는 함수를 호출하거나 generator 표현식을 작성해서 만든다.
- `yield`는 값을 전달하고 실행 상태를 보존한 채 일시 정지하지만, `return`은 함수 실행을 종료한다.
- generator 표현식은 생성 시점에 계산하지 않고, `next()`나 `for`문이 값을 요청할 때 필요한 값만 계산한다.
- generator는 전체 결과를 미리 저장하지 않으므로 큰 데이터를 순차 처리할 때 메모리 사용을 줄일 수 있다.

## 아직 모르는 점

- iterator와 generator가 실행 위치와 지역 변수 상태를 내부적으로 어떤 구조에 저장하는지는 알지 못한다.
- generator가 항상 리스트보다 좋은 것은 아니므로, 결과 재사용 여부와 데이터 크기에 따라 어떤 방식을 선택해야 하는지 더 연습이 필요하다.
- 독립 재현에서 현재 반복 요소와 iterator 자체를 코드 작성 전에 정확히 구분하는 연습이 더 필요하다.

## 면접에서 말할 수 있게 정리

- **iterable과 iterator의 차이는?**
  iterable은 반복할 수 있고 iterator를 만들 수 있는 객체다. iterator는 진행 상태를 기억하면서 `next()`로 다음 값을 주고, 다 소진되면 `StopIteration`을 발생시킨다. `for`문은 내부적으로 이 과정을 반복하다가 `StopIteration`을 만나면 종료한다.

- **generator를 왜 쓰나?**
  결과를 전부 만들어 두지 않고 요청할 때 하나씩 계산하기 때문이다. 결과 100,000개를 저장한 리스트와 generator 객체의 크기를 `sys.getsizeof()`로 직접 비교해서 차이를 확인했다. 다만 결과를 여러 번 재사용해야 하면 리스트가 나을 수 있어서, 선택 기준은 더 연습이 필요하다.

- **막혔던 부분은?**
  서버 점검 코드를 독립 재현하면서 `for`문으로 이미 꺼낸 딕셔너리에 `next()`를 다시 썼고, 비교 대상도 잘못 잡았다. 반복 변수에 실제로 무엇이 들어 있는지와 조건식의 좌우 항을 다시 확인해서 수정했다.
