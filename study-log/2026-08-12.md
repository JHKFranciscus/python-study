- `justify-content`, `align-items`, `flex-direction`, `gap`, `flex-wrap`을 직접 바꿔가며 동작 확인
- 상단 내비게이션과 카드 영역에 Flexbox 실제 적용
- 프로필 + 활동 카드 페이지 독립 재현
- 알고리즘에서 `반복 → 조건 확인 → 누적` 패턴 학습 후 독립 적용
- 중첩 Flexbox에서 배치 대상과 직접 부모를 찾는 추가 학습

---

## 막힌 부분 → 시도 → 배운 것

### 1. 가로 중앙 정렬을 cross axis로 잘못 판단했다

- **시도** — `flex-direction`을 바꿔가며 main axis와 cross axis가 어떻게 달라지는지 화면으로 직접 확인했다.
- **배운 것** — 축은 가로/세로로 고정된 게 아니라 `flex-direction`에 따라 바뀐다. `justify-content`는 main axis, `align-items`는 cross axis 기준이다.

### 2. 카드 안의 `h3`와 카드 자체 중 무엇을 배치 대상으로 잡을지 혼동했다

- **시도** — 부모 영역에 `border`를 넣어 어떤 요소가 어느 부모 안에 묶여 있는지 눈으로 확인했다.
- **배운 것** — 먼저 무엇을 서로 배치할지 정한 뒤, 그 요소들의 직접 부모를 flex container로 만들어야 한다. 하나의 flex item 내부를 다시 배치해야 하면 그 내부 부모에도 별도의 Flexbox를 적용할 수 있다.

### 3. 링크들이 기본적으로 조금 떨어져 보이는 것을 `gap`이 적용된 결과와 혼동했다

- **시도** — 링크 영역에서 `gap`을 제거하고 `display: flex`를 추가하며 차이를 비교했다.
- **배운 것** — `gap`은 화면상 우연히 생긴 공백과 달리 item 사이 간격을 명시적으로 지정한다.

### 4. 독립 재현 첫 제출에서 링크 영역의 `display: flex`와 프로필 카드의 공통 스타일 조건을 빠뜨렸다

- **시도** — 완성 코드를 받지 않고 요구사항을 다시 보면서 직접 수정했다.
- **배운 것** — 요구사항이 여러 개일 때는 마지막에 조건을 하나씩 대조하는 점검이 필요하다.

---

## 추가로 확인한 것

- 브라우저 폭을 줄여 `flex-wrap`이 실제로 다음 줄을 만드는지 확인했다. → `flex-wrap: wrap`은 공간이 부족할 때만 item을 다음 줄로 넘긴다.
- 알고리즘에서는 여러 데이터를 하나씩 확인하면서 조건에 맞는 경우의 개수나 합계 등 필요한 값을 누적할 수 있다.

---

## 오늘의 핵심 규칙 3가지

1. **배치 대상 → 직접 부모 → flex container** 순서로 판단한다.
2. `justify-content`는 main axis, `align-items`는 cross axis. 가로/세로로 고정해서 외우지 않는다.
3. 중첩 구조라면 안쪽 부모에도 Flexbox를 따로 적용한다.

## 아직 부족한 부분

- HTML 계층이 복잡해졌을 때 배치 대상과 직접 부모를 한 번에 찾는 속도가 아직 느리다.
- Flexbox property를 가로/세로가 아니라 main axis / cross axis 기준으로 바로 판단하는 연습이 더 필요하다.
- 요구사항이 여러 개인 독립 재현에서 CSS 조건을 일부 빠뜨리지 않도록 마지막 점검이 필요하다.
