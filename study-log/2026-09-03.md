# 2026-09-03 공부일지

**한 줄 요약** — Flask + Jinja2 + PyMongo로 CRUD 전체를 연결했다. 게임 CRUD는 새 파일에서 직접 구현했고, 영화 CRUD는 독립 재현했지만 상세 → 수정 이동 하나를 빠뜨렸다.
---

## 오늘 한 일

1. **화면 출력** — `render_template()`과 Jinja2로 Python/MongoDB 데이터를 HTML에 출력했다. `{{ }}`로 값을 출력하고 `{% for %}`, `{% if %}`로 반복과 조건을 처리했다.
2. **조회 분기** — 여러 document는 `find()`, 하나의 document는 `find_one()`으로 조회해서 각각 목록 화면과 개별 화면에 연결했다.
3. **`_id` 전달** — MongoDB `_id`를 HTML의 URL/form에 넣어 Flask로 전달하고, 받은 문자열을 `ObjectId()`로 변환해서 특정 document를 찾았다.
4. **CRUD 연결** — HTML form의 POST 요청과 `request.form`으로 Create / Update / Delete를 MongoDB와 연결했다. 작업 후에는 `redirect(url_for("home"))`로 목록을 다시 요청해 변경된 DB 상태가 화면에 반영되게 했다.
5. **직접 구현** — 게임 관리 CRUD를 새 파일에서 직접 구현했고, 영화 관리 페이지는 목록 / 등록 / 상세 / 수정 화면을 분리해서 CRUD 전체를 다시 구현했다.
6. **흐름 확인** — 서버 사이드 렌더링에서 Jinja2가 서버에서 HTML을 완성한 뒤 브라우저에 전달한다는 요청·응답 흐름을 확인했다.

---

## 오늘 걸린 것 3가지
조회 key
### 1. `find_one()`에서 MongoDB의 `_id`를 `id`로 잘못 썼다

- **막힌 점** — 조회 결과가 `None`이 됐고, `None["title"]`을 실행하면서 `TypeError`가 발생했다.
- **시도한 것** — `find_one()`의 조건과 반환값을 추적해서 조회 key를 `_id`로 수정했다.
- **배운 점** — `find()`는 여러 document, `find_one()`은 document 하나가 필요할 때 쓴다. 그리고 URL로 전달되는 `_id`는 문자열이고 MongoDB의 `_id`는 `ObjectId`라서, 조회·수정·삭제 전에 타입을 맞춰야 한다.

### 2. 게임 CRUD에서 타입과 필드명을 놓쳤다

- **막힌 점** — `request.form`의 `price`를 문자열 그대로 저장했고, 요구된 필드명 `name` 대신 `title`을 사용했다.
- **시도한 것** — form 데이터가 문자열로 전달된다는 점을 확인하고 `price`, `year`, `rating`에 `int()` 변환을 적용했다. MongoDB document의 필드명, form의 `name`, Jinja2에서 사용하는 key가 서로 일치하도록 수정했다.
- **배운 점** — `<input type="number">`라도 `request.form`으로 받은 값은 문자열이라서, 필요한 경우 직접 정수로 변환해야 한다.

### 3. 영화 CRUD 재현에서 상세 → 수정 이동을 빠뜨렸다

- **막힌 점** — 상세 화면에서 수정 화면으로 이동하는 기능 하나를 누락했다.
- **시도한 것** — 영화 상세 화면에 현재 document의 `_id`를 포함한 수정 링크를 추가했다.
- **배운 점** — 상세에서 수정으로 넘어가려면 그 document의 `_id`를 링크에 실어서 보내야 한다.

---

## 흐름에서 배운 점

- Jinja2는 브라우저가 아니라 서버에서 실행되고, 브라우저는 완성된 HTML을 받는다.
- `POST → 302 redirect → GET → 200` 흐름을 통해 데이터 변경 후 최신 목록을 다시 보여줄 수 있다.
- 최신 DB 상태가 필요한 조회는 route 함수 안에서 실행해야 요청마다 현재 데이터를 가져올 수 있다.

---

## 아직 부족한 부분

- Flask + PyMongo + Jinja2 CRUD의 전체 연결은 직접 구현할 수 있었지만, 필드명·타입·화면 이동 같은 세부 명세를 끝까지 확인하는 부분에서 누락이 있었다.
- 영화 CRUD 독립 재현은 핵심 구조를 직접 만들었지만, 상세 → 수정 이동 기능 하나를 빠뜨려서 완전 독립 성공은 아니었다.

---

## 내일

- CRUD 기능 자체뿐 아니라 필드명, 데이터 타입, HTTP method, `_id` 전달, 화면 간 이동까지 명세 전체를 확인하는 습관을 적용한다.
- 오늘의 미완전 독립 성공을 이유로 예정된 다음 진도를 임의로 변경하지 않고 기존 커리큘럼대로 진행한다.
