## 2. 이번 주에 배운 내용

### HTML

HTML의 기본 문서 구조부터 시작했다.

`head`와 `body`의 역할을 구분하고 목록, 링크, `div` 등을 이용해 콘텐츠를 구성했다. 이후 `header`, `main`, `section`, `footer` 등의 semantic HTML을 사용했다.

semantic HTML은 단순히 화면의 영역을 나누는 것이 아니라, **콘텐츠의 의미와 역할에 맞는 HTML 요소를 선택해서 문서의 구조를 표현하는 것**이라는 점을 학습했다.

### CSS 기본

HTML과 별도의 External CSS 파일을 연결하고, tag·class·id selector를 사용하는 방법을 학습했다.

여러 CSS가 같은 요소에 적용될 때 어떤 스타일의 우선순위가 높은지 확인하면서 specificity와 상속도 함께 학습했다.

단순히 CSS property의 의미만 보는 것이 아니라 실제 브라우저에서 어떤 스타일이 최종적으로 적용되는지 확인했다.

### Box Model

HTML 요소가 다음 구조로 이루어진다는 것을 학습했다.

`content → padding → border → margin`

또 `box-sizing: border-box`를 사용하면 지정한 `width` 안에 content뿐 아니라 padding과 border까지 포함된다는 점을 확인했다.

### Flexbox

이번 주 중반부터는 Flexbox를 중심으로 페이지의 배치와 정렬을 연습했다.

`display: flex`, `flex-direction`, `justify-content`, `align-items`, `gap` 등을 이용해 navigation, 카드, 버튼 등을 가로 또는 세로 방향으로 배치했다.

처음에는 property의 역할을 익히는 데 집중했지만, 실제 페이지를 만들면서 **Flexbox에서는 무엇을 배치하려는지 먼저 찾고 그 요소들의 직접 부모를 flex container로 만들어야 한다**는 점이 더 중요하다는 것을 확인했다.

### Bootstrap

Bootstrap의 class를 이용해 button, badge, spacing 등을 적용했다.

모든 디자인을 Bootstrap으로 처리하는 것이 아니라, 반복적으로 사용할 수 있는 공통적인 UI는 Bootstrap을 사용하고 페이지마다 필요한 고유한 레이아웃과 디자인은 직접 CSS로 작성했다.

이를 통해 Bootstrap과 직접 CSS를 함께 사용하는 방법을 연습했다.

### transition과 animation

`:hover`, `transform`, `transition`을 사용해 버튼 등의 상태가 변할 때 변화 과정이 부드럽게 보이도록 만들었다.

또 `@keyframes`, `animation`, `translateY()`, `opacity`를 사용해 페이지가 열릴 때 요소가 아래에서 위로 이동하면서 나타나는 효과를 구현했다.

### 알고리즘

리스트를 순회하면서 `max()`와 `.index()`를 사용하지 않고 최댓값과 그 위치를 직접 찾는 방법을 연습했다.

현재 값과 지금까지 저장한 최댓값을 비교하고, 더 큰 값을 발견하면 **최댓값과 해당 위치를 함께 갱신해야 한다**는 흐름을 다시 확인했다.

### CS — Reflow와 Repaint

브라우저 렌더링 과정과 관련해 Reflow와 Repaint를 학습했다.

요소의 크기나 위치처럼 layout에 영향을 주는 값이 변경되면, 브라우저가 요소의 크기와 배치를 다시 계산하는 **Reflow**가 발생한다.

반면 `background-color`처럼 layout을 변경하지 않고 화면에 보이는 모습만 달라지는 경우에는, 요소를 다시 그리는 **Repaint**가 발생한다.

## 4. 가장 많이 막힌 부분과 직접 확인한 과정

이번 주에 가장 많이 막힌 부분은 CSS property 자체보다 **그 CSS를 어느 HTML 요소에 적용해야 하는지를 판단하는 것**이었다.

Flexbox를 처음 사용할 때는 여러 카드를 가로로 배치하고 싶으면 각각의 카드에 `display: flex`를 적용해야 한다고 생각하는 경우가 있었다.

예를 들어 다음과 같은 구조가 있다고 하면,

```html
<div class="cards">
    <div class="card">Python</div>
    <div class="card">HTML</div>
    <div class="card">CSS</div>
</div>
```

처음에는 배치하려는 요소인 `.card`에 Flexbox를 적용하려고 했다.

```css
.card {
    display: flex;
}
```

하지만 이렇게 하면 각각의 카드가 자신의 내부 요소를 배치하는 flex container가 된다.

세 개의 카드를 배치하려면 세 카드의 직접 부모인 `.cards`를 flex container로 만들어야 했다.

```css
.cards {
    display: flex;
    gap: 20px;
}
```

이 차이를 확인하면서 **배치할 요소 자체와 그 요소들을 배치하는 부모를 구분해야 한다**는 것을 이해했다.

화면에서 HTML 구조가 잘 보이지 않을 때는 요소에 임시로 `border`를 적용해 실제 영역이 어디까지인지 확인했다.

또 `display: flex`를 서로 다른 부모와 자식 요소에 넣었다가 제거하면서 브라우저의 배치가 어떻게 달라지는지 직접 비교했다.

Flexbox 외의 CSS에서도 비슷한 기준을 사용했다.

버튼에 마우스를 올렸을 때 버튼 자체가 커져야 한다면 부모 요소가 아니라 실제 변화 대상인 버튼을 selector로 선택해야 했다.

그래서 이번 주 후반부터는 CSS를 바로 작성하기보다 다음 순서로 생각했다.

> **요구사항 확인 → 변화하거나 배치할 대상 확인 → HTML 구조 확인 → selector 결정 → CSS 작성**

이를 다시 두 가지로 줄이면 다음과 같다.

* **여러 요소의 배치를 바꾼다** → 배치할 요소들의 **직접 부모**를 찾는다.
* **특정 요소 자체의 모습이나 상태가 바뀐다** → **그 요소 자체**를 선택한다.

## 5. 이번 주 내용을 말로 설명해 보기

배운 내용을 다시 나열하는 대신, 이번 주 내용을 질문 형태로 바꿔 직접 답해봤다.

**Q. Flexbox를 쓸 때 `display: flex`는 어디에 적용하나요?**

배치할 요소가 아니라 그 요소들의 직접 부모에 적용합니다. 카드 세 개를 나란히 놓는다면 `.card`가 아니라 `.cards`에 적용합니다. `.card`에 적용하면 각 카드가 자기 내부 요소를 배치하는 container가 되어서 원하는 결과가 나오지 않습니다.

**Q. `box-sizing: border-box`는 왜 사용하나요?**

기본값에서는 지정한 `width`가 content의 크기라서 padding과 border가 더해지면 실제 요소는 더 커집니다. `border-box`를 사용하면 지정한 `width` 안에 content, padding, border가 모두 포함되기 때문에 크기를 예상한 대로 맞출 수 있습니다.

**Q. Reflow와 Repaint의 차이는 무엇인가요?**

요소의 크기나 위치처럼 layout에 영향을 주는 값이 바뀌면, 브라우저가 크기와 배치를 다시 계산하는 Reflow가 발생합니다. `background-color`처럼 layout은 그대로인데 보이는 모습만 바뀌는 경우에는 요소를 다시 그리는 Repaint가 발생합니다.

**Q. semantic HTML은 왜 사용하나요?**

`div`로도 화면은 똑같이 만들 수 있지만, `header`, `main`, `section`, `footer`처럼 의미가 있는 요소를 사용하면 각 영역이 어떤 역할인지 문서 구조 자체로 표현됩니다. 화면을 나누는 것이 목적이 아니라 콘텐츠의 의미와 역할에 맞는 요소를 고르는 것이 기준입니다.

## 6. 아직 부족한 부분

Flexbox와 이번 주에 사용한 주요 CSS property의 기본적인 역할은 이해했지만, 새로운 요구사항을 처음 봤을 때 어느 요소를 selector로 선택해야 하는지를 항상 한 번에 정확하게 판단하는 수준까지는 아니다.

일요일 복습에서도 처음에는 배치하려는 요소와 그 요소들의 부모를 혼동한 경우가 있었다.

HTML 역시 원하는 화면이 나온다는 것만으로 끝낼 수는 없다. 일요일 구현에서는 단순히 작업 이름을 표시하는 자리에 `label`을 사용했다가 수정했다. `label`은 원래 form 요소와 연결해서 그 요소의 이름을 나타내는 element이기 때문에, 단순한 텍스트를 표시하는 용도로는 맞지 않았다. 이처럼 HTML element가 가진 의미와 역할까지 고려해서 선택하는 연습이 더 필요하다.

Reflow와 Repaint도 각각 어떤 상황에서 발생하는지는 구분했지만, Reflow가 발생했을 때 Repaint도 함께 발생하는지까지는 아직 확인하지 못했다.

이번 주에는 HTML/CSS의 각 기능을 배우고 하나의 페이지에서 조합해 사용하는 단계까지 진행했다. 앞으로 새로운 웹 개발 내용을 배우면서도 이번 주에 익힌 HTML/CSS를 별도의 힌트 없이 자연스럽게 다시 사용할 수 있는지는 계속 확인해야 한다.

## 7. 다음 주 목표

다음 주에는 이번 주에 배운 HTML/CSS를 다시 처음부터 반복하기보다 이후 웹 개발 과정에서 계속 활용한다.

새로운 기능이나 화면을 구현할 때 HTML/CSS가 필요하다면 완성 코드를 먼저 확인하지 않고 다음 순서를 먼저 적용한다.

> **요구사항 확인 → 대상 확인 → 구조 확인 → selector 결정 → 구현**

특히 새로운 페이지나 화면을 구현하는 상황이 나오면 최소 한 번은 HTML 구조와 CSS 적용 대상을 먼저 직접 판단한 뒤 코드를 작성한다.

구현이 끝난 후에는 단순히 화면이 원하는 모습으로 나왔는지만 확인하지 않고, **왜 그 HTML 요소와 selector를 선택했는지 스스로 설명할 수 있는지도 확인한다.**
