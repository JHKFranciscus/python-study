# 3주차 주간 학습 기록

## 이번 주 배운 내용

이번 주에는 문자열 입력을 정리하는 방법부터 텍스트 파일과 JSON을 이용해 데이터를 저장하는 방법까지 학습했다.

사용자 입력과 검색 대상에 `strip()`과 `lower()`를 적용하여 앞뒤 공백과 영문 대소문자의 차이 때문에 검색이 실패하지 않도록 했다. 검색은 키워드가 전체와 일치하지 않아도 찾을 수 있도록 부분 검색으로 구현했다.

또한 리스트를 처음부터 끝까지 확인하는 순차 검색의 O(n)과 딕셔너리 키 조회의 O(1)을 비교했다.

텍스트 파일에서는 `r`, `w`, `a` 모드의 차이를 학습했고, 파일을 기반으로 메모를 추가·조회·검색·수정·삭제하는 기능을 구현했다.

이후 JSON을 사용하여 리스트와 딕셔너리 형태의 데이터를 저장하고 불러왔다. 저장에는 `json.dump()`를, 불러오기에는 `json.load()`를 사용했다. 파일이 없거나, JSON 형식이 잘못됐거나, 숫자로 변환할 수 없는 입력이 들어오는 경우를 각각 `FileNotFoundError`, `JSONDecodeError`, `ValueError`로 구분하여 처리했다. 잘못된 입력이 들어와도 프로그램이 종료되지 않고 계속 실행되도록 입력 검증을 함께 넣었다.

프로그램이 커지면서 main, service, storage로 파일을 분리했다.

- main: 사용자 입력과 출력, 문자열의 정수 변환, 최종 오류 안내
- service: 검색·추가·수정·삭제와 같은 데이터 처리 규칙
- storage: 파일 불러오기와 저장

이 과정에서 하위 함수에서 처리하지 않은 예외가 상위 호출자로 전파되는 과정도 확인했다.

## 만든 프로그램

이번 주에는 다음 프로그램을 만들었다.

1. 파일 기반 메모 관리 프로그램
2. JSON 기반 학습 기록 프로그램
3. 모듈형 도서 관리 프로그램

모듈형 도서 관리 프로그램에는 다음 기능을 구현했다.

- 전체 도서 조회
- 도서 추가
- 제목 검색
- 가격 수정
- 도서 삭제
- JSON 저장 및 불러오기
- 잘못된 가격 입력 처리
- 파일 및 JSON 오류 처리

주간 복습에서는 기존 코드를 보지 않고 도서 관리 프로그램의 main, service, storage 구조를 다시 작성했다.

## 가장 많이 막힌 부분

이번 주에 가장 많이 막힌 부분은 다음과 같았다.

- `json.dump()`와 `json.load()`의 역할을 혼동한 것
- 딕셔너리를 만들려다가 중괄호 안에 값만 나열해 set을 만든 것
- 파일을 불러오는 함수와 사용자 안내를 출력하는 함수의 역할이 섞인 것
- service에서 처리해야 할 기능과 main에서 처리해야 할 입력·출력을 구분하는 것
- 같은 기능을 main과 service에서 각각 다시 검색한 것
- 예외를 어느 모듈에서 처리해야 할지 정하는 것

SSAFY 문제에서는 25문제 중 13문제를 맞히고 12문제를 틀렸으며, 다이나믹 프로그래밍 유형에서 가장 많이 틀렸다.

## 문제의 원인

처음에는 프로그램이 실행되는지만 확인하면서 각 함수와 모듈의 반환값 및 역할을 명확하게 정하지 못했다.

예를 들어 검색 함수가 검색 결과 자체를 반환하지 않고 `True` 또는 `False`만 반환하게 만들면서, main에서 같은 검색을 다시 수행하는 구조가 생겼다.

또한 입력값을 정수로 변환하는 코드와 `ValueError` 처리를 service에 두어야 하는지 main에 두어야 하는지 구분하지 못했다.

JSON 기록을 만들 때에는 다음 두 문법의 차이를 정확히 구분하지 못했다.

```python
{"topic", topic}    # set
{"topic": topic}    # dictionary
```

첫 번째는 set이고, 두 번째가 key와 value를 가진 dictionary이다.

## 내가 직접 확인한 과정

프로그램을 정상적인 입력으로만 실행하지 않고, 다음과 같은 실패 상황을 직접 만들어 확인했다.

- 파일이 없는 상태에서 실행
- 빈 문자열 입력
- 영문 대소문자가 다른 검색어 입력
- 숫자 자리에 `abc` 입력
- JSON 파일 내용을 일부러 잘못된 문자열로 변경
- 프로그램 종료 후 다시 실행하여 데이터 유지 여부 확인
- 검색·수정·삭제 시 제목의 대소문자를 다르게 입력

예외 전파를 확인하기 위해 storage와 service에서는 예외를 처리하지 않고, main에서 `FileNotFoundError`와 `JSONDecodeError`를 처리하는 코드도 작성했다.

## 수정한 방법

- 파일 불러오기와 저장은 storage에서 담당하게 했다.
- 검색·추가·수정·삭제와 같은 데이터 처리 규칙은 service에서 담당하게 했다.
- 사용자 입력, 출력, 문자열의 정수 변환, 최종 오류 안내는 main에서 담당하게 했다.
- 검색 함수는 `True` 또는 `False`만 반환하지 않고, 검색된 도서 목록 자체를 반환하도록 수정했다.
- 가격 입력은 main에서 `int()`로 변환하고, `ValueError`가 발생하면 프로그램이 종료되지 않고 메뉴로 돌아가게 했다.

## 실제 실행 결과

다음 동작을 확인했다.

- `Python Basics`를 `PYTHON`으로 검색해도 검색된다.
- `python basics`를 입력해도 가격 수정과 삭제가 가능하다.
- 가격에 `abc`를 입력해도 프로그램이 종료되지 않는다.
- JSON 파일 형식을 일부러 망가뜨려도 traceback 없이 빈 목록으로 시작한다.
- 도서 가격을 수정한 뒤 프로그램을 재실행해도 수정 결과가 유지된다.

## 아직 부족한 부분

아직 예외 처리 위치와 모듈 역할을 처음부터 바로 설계하지 못하고, 프로그램을 작성한 뒤 역할이 섞인 부분을 수정하는 경우가 많다.

함수의 반환값을 `True`, `False`, `None`, 리스트 중 무엇으로 정할지 작성 전에 충분히 결정하지 않는 문제도 남아 있다.

SSAFY 문제에서는 다이나믹 프로그래밍 문제의 상태와 점화식을 찾는 연습이 부족하다.
