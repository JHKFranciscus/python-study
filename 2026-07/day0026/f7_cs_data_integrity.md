# 객체의 유효한 상태와 데이터 무결성

## 1. 객체의 유효한 상태

객체의 속성 값이 프로그램에서 정한 자료형과 값의 범위 등의
규칙을 만족하는 상태를 말한다.

현재 Product의 가격은 int이고 0 이상이어야 유효하다.

## 2. 데이터 무결성

데이터가 생성·변경·저장·복원되는 과정에서도
프로그램이 정한 규칙에 맞는 정확하고 일관된 상태로 유지되는 것을 말한다.

## 3. setter의 역할

가격이 생성되거나 변경될 때 같은 검증 규칙을 적용하여
잘못된 값이 내부 속성에 저장되지 않도록 한다.

## 4. JSON 복원 시 검증이 필요한 이유

JSON 문법이 올바르더라도 상품 규칙에 맞지 않는 값이 들어 있을 수 있다.
따라서 파일에서 읽은 값을 객체로 복원할 때도 setter 등의 검증을 거쳐야 한다.


### 문제 1

다음 객체는 파이썬 문법상 생성할 수 있다고 해도 유효한 상품 객체인가?

Product("마우스", -30000)

이유도 작성한다.

답: 오늘만든 프로그램은 '가격은 int여야 한다. 가격은 0 이상이어야 한다.' 라는 규칙이 있는데 -3000은 이를 만족하지 못한 상태이므로 유효한 상품 객체가 아니다

### 문제 2

객체를 만들 때만 가격을 검사하고 이후 변경에서는 검사하지 않으면 데이터 무결성이 유지되는가?

답: 데이터의 무결성은 프로그램이 정한 규칙에 맞는 정확하고 일관된 상태로 유지해야하는데 변경 시에 정한 규칙에 어긋나는 값이 들어갈 수도 있기 때문에 데이터의 무결성이 유지되지 않을 수도 있다.

### 문제 3

JSON 문법이 올바르다는 것과 JSON에 저장된 상품 데이터가 유효하다는 것은 같은 의미인가?

답: 상품의 데이터가 유효다하는 것은 상품의 데이터 값이 프로그램이 정한 규칙을 만족해야하는데 프로그램이 정한 규칙을 만족시키지 않아도 JSON 문법이 정한 규칙을 만족시키면 JSON 문법이 올바른 것이기 때문에 다른 의미이다. 

### 문제 4

다음 코드에서 setter 검증이 한곳에 모여 있다는 장점은 무엇인가?

self.price = price
product.price = new_price

답: 규칙을 한 곳에서 관리할 수 있다는 장점이 있다.

### 문제 5

현재 load_products()는 잘못된 가격에서 ValueError를 발견하지만 처리하지 않아 프로그램이 종료된다. 이 경우에도 검증 자체는 작동한 것인가? 데이터가 잘못된 객체로 저장되는 것은 막았는가?

답: 조건에 부적합하면 프로그램이 종료가 되므로 검증 자체는 작동한 것이다. 그리고 ValueError를 처리하지는 않았지만 프로그램이 종료된다는 것은 ValueError로 인해 더 이상 코드 진행이 나아가지를 않는다는 것이기 때문에 데이터가 잘못된 객체로 저장되는 것을 막았다.
